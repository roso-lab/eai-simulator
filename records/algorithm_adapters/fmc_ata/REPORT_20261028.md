```python
from algorithm.system.coordination.fmc_ata.native_adapter import NativeFMCATAAdapter

provider = NativeFMCATAAdapter(
    source_root="/tmp/heterocoord-algorithms-20261028/fmc-ata",
    python_executable="/home/airs/.cache/heterocoord/envs/fmc-ata/bin/python",
    timeout_seconds=30.0,

decision = provider(task, robots)  # EaiTaskPackage -> AlgorithmDecision
```

Defaults: `/home/airs/.cache/heterocoord/upstream/fmc-ata` and the venv above;
environment overrides: `FMC_ATA_SOURCE_ROOT`, `FMC_ATA_PYTHON`. The parent's
independent source-integrity gate should wrap this provider. The adapter records
imported module hashes but does not claim source attestation.

Required metadata:

- Package: `{"fmc_ata": {"domain": "independent_single_mission_single_player"}}`.
- Each task: one required capability, no prerequisites, and
  `{"fmc_ata": {"position": [x,y,z], "workload": 100, "importance": 1000, "max_players": 1}}`.
- Each active robot: one capability, finite 3D position, and
  `{"fmc_ata": {"speed": 1, "productivity": 1, "status": "idle"}}`.

Inputs explicitly describe single-player missions. Cooperative/fractional task
execution, DAG constraints, busy/multi-ability robots and non-perfect communication
are rejected. No initialize, observation-update or replan semantics are invented.

## Native fidelity and lifecycle

Source: Python AsynchTaskAllocation at commit
`7872a94776cfe21cf58cadf44007382deb650eea`, not the Java FisherMarketSimulator.
The worker imports and calls `solver_fmc_distributed_asy.FMC_ATA.solve(0)` with
original `PlayerSimple`, `TaskSimple`, `MissionSimple`, responsibility assignment,
`calculate_rij_abstract`, perfect communication, and the original static driver's
termination callback. Static-driver settings are preserved: utility level 1,
convergence counter 1, threshold 1e-5, timestamps disabled, original ro=0.9.
Only the driver's exposed NCLO run bound is configured. No learned weights apply.

Native `max_players=1` normalization and native player schedule generation choose
the whole-task schedule. The adapter does not round market fractions or choose
their maximum. It validates whole duration, unique/full task coverage, capability,
and agreement of player and task normalized allocations before emitting assignments.
Per-robot order is preserved; cross-robot execution timing belongs to the executor.
`provenance.native_output` retains fractional market shares, normalized allocations,
raw ordered schedules, scheduling arrival data, bids/utilities/prices, message
counters and final received message contexts. This is not a complete wire trace.

Every call starts a fresh isolated interpreter (`-I -B`), runs in a temporary cwd,
and reaps its subprocess. Wall timeout kills the process group, including native
threads. No retries, schedule repairs or fallback policy exist. Successful native
shutdown checks all solver threads are joined. `NativeFMCATAScheduleError.evidence`
retains an unrepresentable native result; `NativeFMCATAError.evidence` retains
timeout/budget failure evidence. Input scope failures use `UnsupportedFMCATADomain`.

## Executed results and limitations

`native_evidence_20261028.json` contains a fixed 13-run batch, including every
failure; repetitions measure asynchronous variation, not retries to select a win.

| Outcome | Count |
|---|---:|
| Native complete schedule admitted through TaskRunner | 7 |
| Native incomplete/inconsistent schedule rejected | 3 |
| Native timeout, process killed and reaped | 2 |
| Native NCLO budget failure | 1 |

Accepted runs include baseline, swapped robot positions, changed task positions,
workload and importance, and heterogeneous capabilities. The accepted baseline
maps t0/r0 and t1/r1; accepted swapped-position cases reverse the robot assignment.
Changed-task accepted cases also reverse assignments and retain the new native
duration 37. Raw non-integral shares remain in the JSON.

The original asynchronous driver can stop when task phase-II flags are set before
player schedules have received all updates. Some cases therefore return incomplete
or stale schedules. Single-player runs also exhibited native blocking, bounded by
the subprocess timeout. These are unresolved upstream limitations; changing the
termination or draining/recomputing schedules would change the tested algorithm.
Phase-II flags are not an optimality certificate. No affected run is counted as
an admitted native decision.

Final recorded tests against origin/HeteroCoord@769e31d8: **15 passed, 4 xfailed**
(19 collected, no ordinary failures). XFAIL explicitly marks observed original
asynchronous schedule limitations and is **not native passed evidence**. Initial
local runs passed 19/19; later repetition exposed the above nondeterminism, so the
first run is not reported as a stability guarantee. JUnit results are retained in
`pytest_origin_20261028.xml`.

The imported TaskRunner SHA-256 was independently compared with
`git show 769e31d8:task/runner.py` and matched. Source files, including pre-existing
untracked bytecode, have identical before/after hashes. Isolated environment:
Python 3.10.12, numpy 2.2.6, pandas 2.3.3, pytest 9.1.1.
