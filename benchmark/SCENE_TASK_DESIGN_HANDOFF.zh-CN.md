# HeteroCoord 场景任务设计工作流与接手说明

更新：2026-10-16。

## 1. 接手目标

本工作负责把论文中的异构多机器人协作关系，逐场景转化为自然、可观察、后续可执行的 benchmark 任务设计。当前阶段不直接冻结坐标、机器人型号、时间阈值或物理技能；先确认任务语义、合同关系和外部验收证据，再交给语义地图、技能和 evaluator 开发者绑定。

接手者应继续完成：

1. 根据用户对具体场景的观察和想法，逐个编写任务卡；
2. 维护已确认合同覆盖，避免把候选或扩展计作已覆盖；
3. 为地图/技能开发者整理对象、区域、能力和外部证据需求；
4. 在实现条件就绪后，再将确认的任务语义迁移到可执行 catalog、oracle 和实验配置。

## 3. 每个场景的工作流

用户通常只会提供场景名、截图/渲染观察和一段自然语言设想。按下面流程推进。

### 3.1 区分证据层级

- 用户明确描述：可以作为本轮设计事实，但仍需后续物理绑定；
- 截图或机器渲染可见：记录布局和候选区域，不能据此认证对象可抓、门可开或机器人可达；
- 助手新增任务对象或规则：必须标成提案；
- 地图/技能/evaluator 实测通过：才可升级为已认证实例。

状态建议固定使用：备选素材、基于观察的提案、用户已确认任务语义、待地图/技能验证、已认证实例。

### 3.2 先确定终端价值

每个任务先说明为什么属于 Production/logistics、Service/operations 或 Living/public。最终目标必须是场景中的真实价值，例如房间可入住、聚会服务持续可用、访客到达正确区域，而不只是“机器人移动了物体”。一个正式实例只登记一个最终 domain。

### 3.3 写完整团队任务链

任务卡至少包含：

- 场景事实、来源和未知项；
- 共同目标；
- 必要任务分支及依赖；
- 所需能力与允许的能力重叠；
- 信息何时公开、何时需要现场发现；
- 责任、物体和资源如何接续；
- 外部可观察的成功、失败和恢复证据；
- 可选扩展与后续绑定需求。

机器人由被测系统从 `usd/robot` 候选池选择。示例型号只表达能力候选，不能写成固定角色，除非用户明确要求且配置已经登记。

### 3.4 映射合同，但不凑覆盖

检查关系是否真的成立：

- P1：多项必要义务有真实并行机会；
- P2 handoff：责任和必要状态跨执行者转移，接收方继续执行；
- P2 precedence：下游动作执行时，外部前置条件仍有效；
- P3-J：至少两个成员共同完成不可拆的联合义务；
- P3-S：在注册窗口内持续维持服务谓词；
- P4：有注册容量的真实资源，逻辑准入和物理占用均可观察。

复合合同必须满足交互语义，不能因为两个原语出现在同一长任务就自动成立。尤其注意：

- 并行分支最终都完成，不自动是 C-P1P2-01；必须汇合后发生必要责任交接；
- 交接和资源排他同时存在，不自动是 C-P2P4-01；资源准入必须是正式交接条件；
- 一组联合搬运和一项普通任务争用通道，不是 C-P3JP4-01；需要多组真实联合义务；
- 找到物品后让另一机器人去拿，是 P2 找物接力；没有持续服务谓词时不是 P3-S；
- 补给循环和共享台面同时存在，不自动是 C-P3SP4-01。

### 3.5 用户确认后才更新覆盖

助手提出的方案先标“提案”。用户明确接受宏观方向或核心关系后，才把任务卡升级为“已确认任务语义”并更新覆盖表。确认不等于物理认证：坐标、阈值、能力、oracle、common 配对和执行结果仍保持待验证。

### room_06：跨层图书接力与重物联合搬运

状态：2026-10-14 用户确认两层复式家庭场景，含天井、无楼梯，一楼和二楼均有书架。任务由两个串行阶段组成：二楼机械臂从书架取书，放到二楼平地/桌面，由无人机经天井运到一楼平地/桌面，再由一楼机械臂放入一楼书架；之后由两台机械臂共同搬运一个超过单臂载重但不超过无人机登记载重的同层重物。两个阶段不并行，具体顺序在实例中预注册。

- 书籍阶段的主要关系是 P2 precedence 和 P2 handoff：二楼传递面稳定后无人机才能取书，一楼传递面稳定后机械臂才能接收；书籍身份、目标位置和剩余工作必须随责任交接传递。
- 重物阶段是 P3-J 候选：两个机械臂必须同时支撑、同步移动并稳定放置，轮流搬或一台跟随不能替代联合动作。
- 由于无人机载重可能覆盖该重物，必须另行注册无人机不能替代双臂的抓取、尺寸、稳定性、室内飞行或安全规则；否则联合搬运不是必需义务。
- 本版将重物限定为同层搬运；没有楼梯时，跨层重物任务需要额外的升降/传递设施，不能从天井外观直接假定地面机器人可跨层。
- 传递面或天井边缘只有在真实多任务竞争且可记录容量、准入、占用、退出和释放时才登记 P4；当前两个阶段串行，不自动形成 P1 或 P4。
