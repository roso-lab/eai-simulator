## 2. 原子合同边界

### C-P1-01

多个互补义务对共同目标均有必要贡献。它们没有强制先后关系，能力与资源配置允许并行。被测系统可选择串行执行；实际时间重叠作为诊断，只有违反已注册约束才判违规。最终由外部谓词验收，不要求额外验证机器人。

### C-P2-01

交接对象可以是物体、订单、任务状态或服务责任；必须可追踪责任转移与后续执行。已确认的最低状态包语义包括：责任身份、义务状态、目标身份、已完成与剩余工作、最近可验证状态、位置或范围、约束、事件原因、版本和时间。字段含义由场景绑定，不能将 evaluator 隐藏真值作为模型输入。

当前已确认的是责任交接合同；不据此把论文中所有 precedence 关系都缩减为责任转移。具体 release、接收准备、accept 的时间约束还需形成一致的协议定义。

### C-P2-02

A 建立 B 执行动作所需的外部条件，两者各自承担原义务，不要求责任转移。允许 B 提前规划、移动至等待位置等准备；约束绑定到实际依赖动作，执行时前置条件必须仍然有效。实例需注明条件完成后持续有效，还是可能失效并需重新检查。完成消息不替代物理条件；被测系统通过允许的观测或通信获取信息，evaluator 独立判断实际条件与时间约束。

如果维持条件本身要求持续服务，应审查完整关系签名是否加入 P3-S。纯 precedence 的支持集与 handoff 指标分母分别登记。

### C-P3J-01

至少两个具备资格的参与者共同完成一个不可拆分的联合义务，具有注册的 coalition 大小约束、同步窗口、外部 joint predicate 与稳定完成条件。参与者身份由系统分配，单机器人串行完成不能代替这个联合义务。

### C-P3S-01

定义服务范围、注册时间窗口、外部服务谓词以及允许空窗。记录服务建立、空窗开始、恢复及持续恢复。普通“搜索完一次”不足以建立连续服务合同；场景必须说明每个时刻需要维持的服务条件。

服务结果与事件处理分别报告：覆盖空窗、有效响应、计划性延后、行动开始和持续恢复。计划性延后要求已提交可执行计划，包括剩余义务、接替者、合法资源与执行窗口；口头承诺不充分。计划提交证据与外部响应端点的映射仍需按论文定义校核，不能自动将提交时刻当作恢复时刻。

### C-P4-01

同时需要逻辑资源证据与物理占用证据：请求、准入、锁或租约、释放，以及实际进入、退出、占用数和危险状态。容量的计量单位必须注册，例如机器人、协作组或空间占用，不能把“一组”误计为“一个机器人”。

## 3. 复合合同的交互

### C-P1P2-01

`A_ready AND B_ready → convergence → responsibility handoff → continuation`。

分别保留前置工作与交接证据。A、B 必须具有真实并行机会；如果 B 的内容依赖 A 的输出，应重新检查义务图，不能仅为保留标签而称为并行。

### C-P2P4-01

正式交接以共享资源合法准入为前提。责任对象与资源是不同身份，责任接收不能代替资源获取，锁释放也不能代替责任交接。接收方在合法资源窗口内继续工作，使用完成后释放。

### C-P3JP4-01

已讨论并接受的实例是 A+B、C+D 各自执行真实联合任务，竞争同一排他通道；两组之间的直接关系是资源争用，不是相互接替。系统决定先后顺序、合法准入、等待及资源释放，各组内部维持联合动作。

该示例的具体成员不是通用固定配置。若场景额外要求组间责任交接，登记 P2；若义务图还满足其他强制原语，也保留完整关系签名，不能凭合同名称删掉关系。资源保护区间须明确到任务图上的起止节点，不能在物理占用仍存在时提前释放。

### C-P3SP2-01

服务窗口内完成责任及状态交接，由接替者继续服务。服务空窗与交接是否合法分别计量：交接成功仍可能违反连续性约束，覆盖未中断也不能替代交接证据。

正常换班与突发退出是不同事件条件。具体故障后的释放方式见第 5 节已确认规则。

## 4. 测量与配对的共同边界

- 合同关系签名在运行前注册。要求 P2 的合同若未发生合法交接，应保留 P2 的未满足结果，不能事后降为纯 P3-S 并从交接分母中移除。
- 长任务中的阶段观测可以分别评分，但不能仅因切分阶段就视为独立统计样本。正式推断仍需保持论文的 base-instance 标识、重复层级和配对风险集。
- 成员加入退出、能力丢失、通信退化等是注册事件条件。动态工作集变化按版本与受影响义务记录；不能仅因可行性改变就自动排除结果。
- 响应、持续恢复、任务成功、安全停止、事件后不可行、观察窗结束以及证据缺失分别记录。合法 safe-stop 不等于 handoff 成功；观察窗内未恢复也不自动证明永远无法恢复。
- 一个复合合同的语义审定不代表它已能在所有领域跨域配对。common 资格需要场景实例的合同、观察权限、测量语义及配对证据认证。
- 用户确认机器人池从 `usd/robot` 选择，允许多类型、多实例及不同空间位置，由被测系统依据机器人简历自主调度。示例型号和数量不构成固定角色分配。候选池及初始位置按实验条件登记，实际运动成本据轨迹记录；能力简历必须绑定实际配置，动态状态遵守公开观测/通信权限。详见实施方案 §5.7。

## 5. 突发退出后的接管规则（两种路径已确认）

2026-10-11 用户确认按以下两种路径定义接管。前面用一条 `release → handoff → accept` 描述所有退出情形，无法覆盖已经损坏且不能发消息的机器人。

1. 可通信的计划性交接：原执行者提供当前状态，接收方准备，按注册规则完成责任转移并继续。
2. 无法通信的突发接管：被测系统通过允许的观测发现失联或失能，依据注册的撤销、租约或失效规则终止旧责任，选择接替者，用已有公开记录或主动重新获取的信息恢复剩余工作。

第二条不能伪造原机器人发出的 release 或故障后的最新状态包。Fleet 只执行身份、路由、锁和审计规则；发现语义事件、选择接替者、补充信息与重规划仍由被测系统完成。

记录 `state_source`、`state_version`、`state_age`、`missing_fields`、`release_basis`、`response_evidence` 与 `recovery_evidence`。这些是待审计记录建议，不自动扩充给被测系统的信息权限。缺失信息需要由系统在公开权限内补齐或明确处理，外部 evaluator 只评分。

两种路径的语义已确认；撤销权限、触发阈值、信息时效和外部接管谓词仍需在可执行协议中注册。接收方的准备确认与正式责任 accept 必须区分；不能把同一 release/accept 关系在不同例子中任意倒序。论文的交接间隔使用正式外部事件，两种路径需要分别明确相应证据。

## 6. 覆盖审查：已有基础，但尚未穷尽（建议待审）

### 6.1 已补纯前置依赖合同

用户已确认 `C-P2-02`（discussion-v2，与废弃旧 catalog 的同名项无继承关系）：A 的外部条件是 B 执行依赖动作的前提，但不要求 A 把自己的责任交给 B。允许提前准备，执行依赖动作时条件必须仍有效。

例如 A 清除路障，B 运输物资；B 一直承担运输义务，A 一直承担清障义务。记录前置条件成立、B 启动、两事件时间差和约束满足情况。论文将 precedence edge 与额外带 release/accept 的 handoff 区分，当前责任交接合同不能替代这类前置依赖。

保留 P2 关系标签，并登记 edge_kind；纯前置依赖不能伪造 release/accept 事件，也不能仅凭 P2 标签就混入责任交接的主指标分母。正式支持集需要按具体关系类型注册。

### 6.2 应补已有合同的实例变化和测量边界

| 补充内容 | 挂载位置 | 为什么需要 |
|---|---|---|
| 多资源循环等待、长期等不到资源 | P4 的资源图与机会/停滞规则 | 容量始终合法仍可能完全不推进；普通等待不能无证据标为死锁 |
| 多个前驱、多个后继、多次交接 | P1/P2 义务图参数 | 一次两节点交接不足以代表长链，但节点数变化不必生成新原语 |
| 状态过期、部分记录丢失、重复或延迟到达 | P2 状态版本及通信处理条件 | 接收到消息不等于获得可继续执行的有效状态 |
| 新任务到达、任务量增加、成员加入退出、能力变化 | 注册事件轴与受影响工作集 | 重规划可改变 assignment；不应把每次变化做成新机制 |
| 正常、可恢复、事件后不可行、安全停止条件 | 各合同事件实例 | 同一系统既需展示恢复，也需识别无法合法继续的情况 |

这些属于合同参数或条件覆盖，仍需事先注册，不能执行后任意补充或改变分母。P4 同时报告排他安全、工作进展与有证据的 stall；长期未动不能直接证明逻辑死锁。

### 6.3 已确认的新增交互：C-P3SP4-01

用户已确认 `C-P3SP4-01`：维持连续服务，同时调度有限共享资源。例如两台具备监控能力的机器人轮流维持区域覆盖且共用一个充电位；初始电量、移动时间、充电速率和服务窗口需注册并保证存在可行调度，窗口须足够长以产生实际补能需求。系统需要安排谁继续服务、谁充电、何时切换，避免充电位合法使用但服务出现空窗。接替机器人可先到达服务区并建立有效覆盖，原机器人再离开；短暂共同覆盖是允许的，不等于充电位可共同占用。

只有场景本身要求正式责任交接时才额外登记 P2。该合同分别记录覆盖与空窗、资源准入与占用、补给过程及任务终止结果；资源合法使用不能替代服务连续性证据。

P1+P4（多个工作流争用资源）、P3-J+P2（联合工作中的责任接替）及更长组合暂列扩展；先检查现有图组合是否已能表达、是否新增独立测量问题和场景配对证据，再决定是否另列 common anchor。不能把五种模板的全部排列组合当成必须执行的矩阵。

### 6.4 结论范围

当前十一个已审定合同触及四类原语及 P3 两个子类型，覆盖若干典型交互；不能声称覆盖所有协作关系、所有拓扑或所有事件。具体跨域 common 资格仍待认证。P4 等待与停滞规则已确认，下一项为事件条件下可行性与恢复的实例设计。

### 6.5 P4 等待与停滞（已确认）

不增加新合同 ID，扩展 C-P4-01 及含 P4 的复合合同。区分资源排他是否满足、有效工作是否推进、被测系统是否提交有效调整以及调整后是否恢复。

示例：A 已预约操作台并等待扫描器，B 已预约扫描器并等待操作台；两者完成各自作业都需要这两项资源。合同应声明预约能否取消、占用能否安全释放、租约到期及替代方案，系统可选择预防或解除等待的策略，不能由 Fleet 自动代做语义调度。

普通排队不违规；延后处理是否违规取决于注册的 deadline、等待上限或服务约束。超出注册无进展窗口可以形成 stall 证据，但循环等待图或超时本身不足以证明逻辑死锁；需要核对释放、租约到期和可行替代路径。主动释放后恢复，记录停滞及其解除；不能用最终完成抹去中途停滞，也不能用一度等待认定整个任务必然失败。

用户已确认：资源安全、工作进展、调整响应、恢复分别记录，避免“无冲突就是成功”和“等待就是失败”。适用于 C-P4-01 及所有包含 P4 的复合合同，不增加合同 ID。

## 7. 事件条件与场景任务的连接（逐项审定）

11 个合同是机制库，每个场景选择适合其实际任务的合同及必要组合。正式矩阵按目标指标、机制与事件适用性登记，不要求每个场景运行所有合同和所有事件的笛卡尔积。未覆盖组合须显式保留覆盖状态。

### 7.1 成员退出（高层语义已确认）

为适用的成员退出实验预注册两类实例：

- 退出后仍可行：可由剩余成员合法完成剩余义务，考虑能力、资源、deadline、位置及状态获取成本，而非仅检查有无同型号替补。评价有效响应、重规划、受影响工作的持续恢复及成本。
- 退出后已不可行：有可检查证据表明剩余团队无法在注册约束内完成。评价可行性识别与规定的安全停止；不可行状态、实际安全停止和任务完成分别记录，不强迫恢复成功。

认证未决时保留 unverified，不能用被测系统失败反推任务不可行。两类通过事先登记的团队配置和退出事件构造，按预定证据规则认证，不能按最终表现筛选。每个实例内部的 nominal/reference 和退出分支保持可比；两种不同配置不自动构成相互的因果对照。

以上退出分类已获用户确认，具体场景方案和数值参数仍待审定，尚未冻结为必跑实验矩阵。

### 7.2 成员加入（高层语义已确认）

按加入时的任务状态区分：补足完成剩余义务所缺少的能力或容量；在原本可行的任务中提供有用增援；在当前剩余任务中没有必要立即投入。分类须依据注册的能力、资源、剩余工作和时限，不能按被测系统最终是否使用新成员倒推。

不把“必须重新分配任务”或“新成员必须执行动作”设为普遍成功条件。检查合法纳入、能力信息是否按规则可见、必要义务是否完成、原有职责是否被破坏，以及实际进度、服务和成本。保持有效的现有计划可以是合理选择，但不能据此宣称系统已经识别并响应了加入事件；没有证据的识别状态保留未知。

只有注册的受影响工作与恢复条件适用时，才进入对应 D4 响应/恢复统计。单纯增援不自动成为故障恢复；若设计退出后再加入，应事先注册非终局等待/安全保持与后续恢复的生命周期，不能在已终止的 episode 中直接复活任务。

用户已确认以上三类成员加入情况及按需接入原则；具体场景选择适用情况，不要求每个场景全部覆盖。

### 7.3 任务进行中新增需求（高层语义已确认）

新增需求作为事件条件，明确新增义务、公开到达时刻、优先级、期限以及与已有义务的关系。不默认取消原有任务，不把新增需求等同于必须立即抢占，也不新增机制合同 ID。

优先区分可在约束内排队处理的新增工作、需要调整现有安排的紧急工作，以及经认证已超出团队可行承载范围的工作。紧急程度与可行性分别登记；认证未决保留 unverified，不能由系统失败倒推超载。

评价分别保留有效接纳/安排的证据、新增义务的实际完成、原有义务的进度和约束违例。合法延后需要可执行安排，口头应答不够；拒绝、延期或降级仅在任务事先允许时才是合法处置，不能由被测系统自行删除义务。超载不自动要求整个团队停止，安全处置范围依任务约束登记。

新增需求未必存在“恢复到事件前状态”的合理目标；对应 D4 统计须先登记受影响工作及事件后有效服务目标，不能直接套用故障恢复分母。

用户已确认：新增需求与原有义务一起评价；预先允许的合理拒绝或协商延期可计为有效处置，但与全部任务完成分开记录。具体场景、时限和允许的处置方式仍待实例化。

### 7.4 通信退化（高层语义已确认）

依论文 D2，在保持任务合同与干预前状态一致的条件下，登记延迟、丢失或容量限制及其作用链路、方向、消息范围与持续时间。不得通过未受约束的共享状态绕过通信条件；也不默认切断所有观测、控制或安全通道。公开本地观测、既有状态和备用通道的可用性均须提前登记。

行为审定围绕三种信息状态：已有有效信息足以支持继续执行；依赖的关键新信息尚未获得、需等待或通过允许的渠道核实；通信恢复后需处理积压、过期或重复消息并核对当前责任与任务状态。这些是可出现的情形，不是要求每次事件依次经过的阶段。

不把每次断联都等同于成员退出，也不要求统一停机或统一重规划。允许在有效信息及授权范围内继续独立工作；涉及尚未成立的前置条件、未确认的交接或资源授权时，不能凭消息已发送推定条件成立。重试、备用通信、主动观测与安全等待都是候选策略，其合法性取决于注册信息与权限规则。

D2 保留正常与退化条件下的任务成功、固定时域进度及论文规定的配对汇总；消息数量、等待、重试和成本用于解释结果，不能替代任务结果。通信链路恢复、有效调整响应与任务实际恢复分别记录；只有适用的注册事件才进入 D4。

用户已确认上述三种信息情形及策略开放原则，不强制统一停机、重试或重规划。具体链路、参数和场景绑定仍待实例化。

### 7.5 共享资源可用性变化（高层语义已确认）

以已有共享资源义务为基础，登记临时关闭、容量下降或替代资源可用性变化。区分约束内可等待、需调整安排但仍可行、已认证不可行；未验证可行性单列，不由被测系统失败反推。保留对资源合法性、进展、有效调整与实际恢复的分别记录，不规定必须绕行或必须等待。

实例须登记资源变化时刻、容量、受影响范围、开放给系统的信息与通知渠道，以及已有预约/锁和在途占用的处理规则。评测器知道的修复时刻不自动公开给系统。优先以尚未进入的机器人为受影响对象；在途关闭另须规定撤离或安全完成规则，不能由环境突然改变容量而自动归责被测系统。

继续未受影响的合法义务可以是合理安排。资源不可用不自动要求全队终止；无法完成的义务、局部安全处置与整队终止条件分别登记。单机器人遇到障碍本身不构成 P4；P4 场景仍需真实共享资源竞争与相应逻辑、物理证据。

用户已确认上述资源变化边界：先设计进入资源之前的变化，允许依据公开信息等待、调整或局部安全处置。在途突发关闭的撤离规则，以及危险条件与安全中断另行审定，避免把资源排队与紧急避险混为同一测量问题。

### 7.6 危险条件与安全中断（高层语义已确认）

区分可恢复的局部安全暂停与论文所指的 certified safe-stop 中断。前者在解除条件经允许的信息渠道确认、责任与执行状态核对后可以继续，不能仅因一度停止就登记为终局 safe-stop。后者针对注册范围内继续执行已不可行或不安全、且规则要求终止的情况；认证安全终止后不在同一 episode 内复活任务。

暂停、撤离、稳定载荷或安全放置等处置须由具体场景定义外部物理谓词、响应窗口、影响范围、公开可见信息与解除权限。安全不能统一简化为速度归零：共同抬载荷时可能需要协调制动、保持支撑或转移至安全位置。未受影响且仍可合法执行的义务不自动停止；整队终止条件须单独登记。

区分被测系统决策、固定技能/控制器保护和仿真器强制保护的证据来源。保护层阻止了危险动作可以形成实际安全结果，但不能据此声称模型主动识别了危险或完成了团队协调；危险指令、保护介入与最终物理后果分别留痕。

分别记录危险触发与可观测时刻、有效响应、外部安全状态、恢复或终局结果。设计须提供可执行的安全应对机会，不能凭环境瞬时施加且系统无法避免的违规归责模型。正确认证 safe-stop 不记作普通失败或任务完成；持续暂停也不能无条件算成功，按注册时限、终局和删失规则判定。D4 主结果仍遵循论文的成员退出面板，其他事件结果按已登记面板单列，不能直接混入主分母。

用户已确认：安全实验区分可恢复暂停与必须认证安全终止，底层自动保护与被测系统主动协调分别记录；具体危险、物理阈值和保护接口尚未冻结。
