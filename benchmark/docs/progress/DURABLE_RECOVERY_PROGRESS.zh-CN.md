## 框架职责与本阶段变化

| 层次 | 本阶段结果 | 尚未解决的边界 |
| --- | --- | --- |
| 实验协议 | 仍由论文及冻结登记决定实验身份、允许重试的故障和计分方式 | 不能把方法失败换成一次新运行 |
| 状态登记 | 十类状态及扩展状态共同进入快照，恢复后逐项读回 | 注册字段齐全不等于真实仿真状态齐全 |
| 持久化 | 类型化清单与数组数据分开保存；外部摘要校验；完整发布且不覆盖旧产物 | 支持的数据类型有限；不保存任意 Python 对象、Torch 设备状态或求解器隐状态 |
| 恢复接线 | 校验源码身份、冻结规则和进程身份；仍只允许诊断 | 数据在新进程可读，不授予旧实验身份的恢复权限 |
| 原生验证 | 新增对底层仿真管理器的独立时钟观测，保留实际失败收据 | 原生时钟恢复、求解状态及完整参与者仍未通过 |
| 评价与发布 | 拒绝把上述软件测试变成正式实验分数 | 正式目录、校准、基线与缺陷对照仍需真实证据 |

十类状态包括：物理世界、时钟、控制器、技能、任务、算法、通信、锁、事件和随机状态。
存盘时保留普通标量、列表、元组、字符串键字典及受支持数值数组的类型、形状、数据；
数组内存步长与共享内存关系不属于存储契约。数值异常、未知类型、缺少参与者、文件损坏
或错误版本都会被拒绝。读取者必须从冻结实验输入取得预期摘要与身份信息，不能让文件
提供自己的可信凭据。当前范围是项目管理的本地目录，不声称可抵御恶意进程同时替换
整个目录树的攻击。

源码摘要由调用方从冻结实验输入提供；存储接口检查摘要绑定关系，不自行重新扫描
整个源码目录。进程身份检查同时覆盖磁盘加载与内存对象使用，避免子进程通过继承
原对象绕过加载检查。这仍不是对调用方自行提供的原生运行驱动的物理认证。

## 实测结果：原生恢复仍失败

原生实验目录为 `artifacts/project_runtime/checkpoint_native_clock_02/`。本次改动只增加
观测与来源摘要，没有改写底层时钟、降低容差或移除失败参与者。三个 EAI 包均从当前
工程 `source/` 导入，原生输出、缓存及检查点均留在当前工程。

| 观察项 | 保存检查点时 | 恢复后 | 判断 |

| 环境步数 | 40 | 40 | 相同 |
| 环境物理步计数 | 160 | 160 | 相同 |
| 上下文物理步数 | 162 | 242 | 未恢复 |
| 原生管理器物理步数 | 162 | 242 | 未恢复 |

位置、关节等可见状态读回通过 `1e-5` 容差；随后执行同一段控制序列的 sham 对照失败，
最大关节速度差约为 `0.062574`。这说明当前恢复提供者没有恢复等价续跑所需的全部状态。
本次证据不能把后续轨迹差异唯一归因于时钟：求解器缓存和其它缺失状态仍需单独验证。

原生子进程退出码为 0，但监督器读取结果后正确判为失败。详细结果和监督器收据分别为
`run/result.json` 与 `supervisor.json`。旧的 `checkpoint_01` 失败产物继续保留。
检查过的已安装接口中尚未找到适用的任意时刻完整恢复入口；这不是对厂商所有可能能力
的否定，也没有通过修改厂商安装文件来伪造成功。

## 阶段反思及后续顺序

本阶段把两个容易混淆的问题拆开验证：文件能否完整保存，以及运行环境能否完整恢复。
前者可以用数据类型、摘要、损坏拒绝和跨解释器测试验收；后者必须用真实底层状态和
后续轨迹对照验收。失败证据应驱动下一阶段的方案选择，不能靠修改计数器或放宽判断
掩盖。

进程确定性重建，必须按论文注册新 base-instance 身份，并重新验证共同边界，不能
冒充旧实例的恢复重试。其后才可开展正式目录认证、独立校准、真实基线和预埋缺陷
验证。D3 分区原文冲突仍等待作者确定，不影响独立工程工作，但阻断正式发布。
