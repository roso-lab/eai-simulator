## 3. 需要您判断与设定的问题（按重要性排序）

### 3.A 【最重要】里程碑的七个语义字段——目前全部空缺

论文规定每个里程碑必须携带以下字段，工程合同里**一个都还没定**。这直接决定 D 系指标怎么算（里程碑权重进完成率、稳定时长决定"何时算达成"），**只能由熟悉论文的人设定**。6 个试点共 32 个里程碑（清单见附录 A）：

| 字段 | 论文含义 | 需要您给的 |
| --- | --- | --- |
| weight（权重 $w_m$） | 进入工作集完成率分母/分子的冻结权重 | 每个里程碑一个非负值（或"全部等权"之类的规则） |
| activation rule（激活规则） | 里程碑何时开始计入活跃集 | 规则（如"前序里程碑全部有效后激活"） |
| stability duration（稳定时长） | 状态须持续多久才算有效达成 | 拍数（如"稳定 50 拍才算"） |
| success necessity（成功必要性） | 是否成功所必需 | 必需 / 可选（影响成功判定） |
| monotonicity（单调性） | 一旦有效是否永久有效 | 是 / 否（失败后可否重新达成） |
| visibility（可见性） | 对被测系统公开还是仅评估器可见 | 公开 / 私有（影响被测系统能否读它做决策） |
| anti-double-counting（防重复计数） | 多次达成如何计一次 | 规则（如"取首次有效达成"） |

**建议交付格式**：直接填附录 A 表格的空列；也可以先给一套适用于全部里程碑的默认规则 + 少数例外的写法（工作量更小）。

### 3.B 违约如何进入 D1 计分

D1 的 $\widehat Q^{\mathrm{org}}$（30 分）由七类要求贡献分解。工程侧需要您定**换算规则**：

1. 一条谓词违约 = 该类一次计数？还是按违约时长/次数加权？
2. 同类多次违约是否封顶？
3. **过程违约与里程碑失效的关系**：比如"扫描工位被双占"这一违约，是否使关联里程碑（both_lots_picked）失效？还是里程碑照常有效、违约独立计入 exclusion 类？（工程当前实现按后者——违约独立记录，待您确认。）
4. 出题人已定"违约只扣分不阻断"——请确认这与论文的 method failure 语义一致（违约是被评分的行为结果，不是基础设施失败，不触发重跑）。

### 3.C 判定状态的论文语义映射

判卷器输出三态：满足 / 违约 / **数据不足**（缺必需事件，fail-closed）。请确认映射：**"数据不足"是否按论文的 unknown-record 处理**（进入漏斗按 unknown 计，不算失败、不可静默补数）？

### 3.D 登记容差与难度分档

1. 出题人为同步窗口选了宽松档 5 秒（250 拍），意图是"考察配合意识而非同步精度"，1–2 秒档留给更难分档——请确认这是否应登记为 nominal（标称）难度层的取值，严格值是否应进入难度分层注册？
2. 覆盖空窗 1 秒、核对时限 10 秒、重叠 ≥1 拍——作为 nominal 层登记值，量级是否合理？

### 3.E 两类 oracle 的边界确认

工程侧的执行边界是：**判卷谓词只判行为，不判可行性；可行性认证归部署 oracle 与 D1 不可行面板；目录校验不拒绝不可行任务**（故意不可行的任务是 D1 考察材料）。请确认此边界与论文意图一致。

### 3.F 可见性总原则

出题人已定：资源占用账本对被测系统**不可见**（约束只写任务描述）。请从论文的观测权限（observation permissions）角度确认：这一定与论文一致（即论文不要求把资源占用状态作为被测系统可读的公开状态）。

### 3.G 新增里程碑的正当性

svc-p2-02 的里程碑序列由出题人插入了 `quarantine_marked`（隔离标记完成，介于 inspection_complete 与 released 之间），用于承载"标记晚于检查"谓词。请确认：该插入符合论文的合同版本语义（里程碑集变更=合同字段变更），还是需要走新的合同版本登记。
