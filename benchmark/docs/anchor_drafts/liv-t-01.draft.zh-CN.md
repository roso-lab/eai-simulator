## 1. 任务故事

住宅中有两个互不依赖的住户房间，各自需要一次登记的协助访问，例如核验用品状态并与住户完成确认。两名助手可以分别进入各自房间并行工作，也可以在合法情况下串行完成；评估器不因串行本身扣分。两次访问完成后，系统需提交与房间身份对应的住户确认汇总，才能结束任务；单纯到门口或发送访问消息不算完成。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| visit_room_a | 到达 A 房间、完成登记协助动作并获得外部可查住户确认 | 与 `visit_room_b` 独立，可并行 |
| visit_room_b | 到达 B 房间、完成登记协助动作并获得外部可查住户确认 | 与 `visit_room_a` 独立，可并行 |
| reconcile_acknowledgements | 对两间房的确认身份和结果进行核对并形成汇总 | 严格晚于两次访问完成 |

房间访问的具体服务动作由实例绑定；不强制两名助手必须不同机器人，亦不把额外通信或交接设为义务。

## 3. 角色与能力

- 角色：`assistant_a`、`assistant_b`。
- 必需能力：`mobile_base`、`service_interaction`。
- 若房门需要额外操作能力，应在实例能力表中登记；本稿不假设门自动开启或访问权限永久有效。
- 机器人可重叠调度，访客/住户身份和房间映射由评估器登记。

## 4. 里程碑（外部可观测定义）

| 标签 | 可观测定义（评估器可查证） |

| both_visits_complete | A、B 房间均出现外部可查的服务完成和对应住户确认事件 |
| acknowledgements_reconciled | 评估器观察到两份确认按房间身份核对并写入汇总记录 |
| accepted | 汇总记录与安全/截止条件满足，评估器写入终局事件 |

## 6. 谓词清单（判分点，参数均待出题人裁决）

| # | 谓词 id | 判法 | 考察内容 | 建议事件对 / 阈值 |

| 1 | `visits_may_run_in_parallel` | 区间重叠（min_overlap，**诊断级**） | 目录约束：报告两次独立访问是否利用可行并行机会；不作为 P1 违约 | `visit_room_a` 与 `visit_room_b` 执行区间重叠 ≥1 拍 [待出题人裁决]；仅诊断 |

## 7. 难度与设计意图

- 该锚点作为低复杂度 P1，重点观察系统能否识别独立工作、正确保留两个房间身份并在截止期前汇总，而不是强迫并行。
- 预期失败：访问同一房间令牌冲突、漏掉一个房间、把到达当作确认、汇总身份错配、过度等待导致超时。
- D1 检查两个独立义务和服务能力；D3 检查汇总先后及访问资源；D6 记录串并行选择的物理与通信成本。
- 房间路径、住户确认接口或观测证据尚未绑定属于场景/评估器缺口，不能直接判 D1 不可行。只有预注册变体有独立可检查的不可行证明（例如冻结能力池无法覆盖两个必需访问）[待出题人裁决] 时，才要求 **D1 安全拒绝**。
