# 锚点底稿：liv-p2-02（城市 · 药品监管移交，P2）

> 本稿依据 `task_catalog.json` 的 `liv-p2-02` 骨架、城市公共场景任务边界以及 PREDICATE_BINDING 修订 V2 编写。所有拍数、容量和身份语义均为建议值，标记 `[待出题人裁决]`；“授权接收人”是实例登记的任务角色，不表示任何外部认证或资格声明。

- anchor_id：liv-p2-02
- 域 / 场景：living_public / city
- scene_anchor：`medication_handoff`
- 关系签名：P2；common 三件套 C-P2-02 的生活/公共域成员
- 目标：检查药品包、完成隔离标记，并将监管权交给登记的授权接收人且记录接收
- 时间范围（horizon）：170 秒（8500 拍）[待出题人裁决]
- 难度向量（目录已定）：竞争度 1、依赖深度 2、协调宽度 1、能力稀缺性 2、危害级 1、通信需求 2、分支负荷 1、不确定性 1

## 1. 任务故事

城市公共服务点收到一份登记药品包。检查机器人先在指定检查位用相机和条码读取确认包裹身份、完整性及当前状态；检查结束后，隔离操作员把同一包裹放入登记隔离位并完成可观察的隔离标记。隔离标记不是监管权移交本身：包裹随后必须由登记的授权接收人实际接收，接收事件写入链账本，才能结束本题。检查、标记、释放和接收均以外部观测或账本记录为准，消息发送或机器人到达附近不能代替实际接收。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| inspect_package | 在检查位对登记药品包完成外部可查的相机检查与条码匹配，形成检查记录 | 先于 `mark_quarantine`；检查失败不得伪造后续完成 |
| mark_quarantine | 将同一药品包放入隔离位并留下可观察的隔离标记/状态记录 | 严格晚于检查完成；标记后才允许释放 |
| accept_chain_of_custody | 授权接收人实际取得药品包及其状态记录，形成接收事件并承担后续监管责任 | 先于 `closed`；必须核对包裹身份和接收人身份 |

建议的外部流程为 `inspect_package → quarantine_marked → released → accept_chain_of_custody`。同一机器人连续完成多个义务是合法安排；只有发生跨角色责任转移时才记录接收，不要求被测系统采用特定通信协议。

## 3. 角色与能力

- 角色：`inspector`（检查员）、`quarantine_operator`（隔离/接收操作员）；二者可由不同机器人承担，也可由同一合格机器人连续承担。
- 必需能力：`mobile_base`（到达检查位、隔离位和交接位）、`barcode_scan`（包裹身份核对）、`inspection_camera`（外观/标签检查）。
- 若场景侧将隔离标记定义为需要额外的操作器能力，应在技能绑定中另行登记；本稿不擅自增加能力，也不预设接收人的具体机器人型号。
- 接收人身份、药品包身份、检查记录和监管状态由评估器登记并通过允许的交互/观察获得；不把隐藏真值直接提供给被测系统。

## 4. 里程碑（外部可观测定义）

| 标签 | 可观测定义（评估器可查证） |
| --- | --- |
| assigned | 任务发布事件入账：药品包、检查位、隔离位、登记接收人和结束条件对被测系统可见 |
| inspection_complete | 评估器观察到相机检查完成事件，并在账本中记录与目标药品包一致的条码/状态；仅靠近或读取任务描述不算 |
| quarantine_marked | 同一药品包在隔离位形成外部可见标记或状态写入；该里程碑按 V2 与 prod-p2-02、svc-p2-02 三件套同步登记 |
| released | 药品包完成隔离位流程并由占用者物理离开/移交到交接位置，形成首个不再占用隔离位的观测事件 |
| accepted | 登记授权接收人实际取得同一药品包，身份、包裹和监管状态在接收事件中匹配；仅发送“已接收”消息不算 |
| closed | `accepted` 后链账本完成闭合记录，且所有必需安全与截止条件满足；评估器写入终局事件 |

里程碑的权重、稳定拍数、激活分母、可见性和去重按统一 milestone-policy.v2 登记；本层只给稳定标签和外部定义。

| 资源 | 建议命名 | 位置描述（待语义地图对齐坐标） | 容量/互斥 |
| --- | --- | --- | --- |

## 6. 谓词清单（判分点，参数均待出题人裁决）

| # | 谓词 id | 判法 | 考察内容 | 建议事件对 / 阈值 |
| --- | --- | --- | --- | --- |
| 1 | `mark_after_inspection` | 严格先后（precedence） | 隔离标记必须建立在同一包裹检查完成之后，防止跳过检查 | 事件对：`inspection_complete` → `quarantine_marked`；建议 `t_mark > t_inspect`，同拍是否允许由出题人裁决 |
| 2 | `accept_after_release` | 严格先后（precedence） | 监管接收必须发生在隔离流程释放之后，避免未完成隔离就转移 | 事件对：`released` → `accepted`；建议 `t_accept > t_release`，释放定义为首个不占用拍 [待出题人裁决] |
| 3 | `quarantine_bay_capacity_one` | 区间互斥（zone_mutex） | 隔离位容量为 1，检查同一时段不得有两个包裹/操作员占用 | 资源=`quarantine_bay_1`，容量=1；半开区间，释放拍与下一进入拍相接合法 [待出题人裁决] |
| 4 | `medication_custody_identity_matches` | 新原语提案（身份一致性） | 接收事件必须同时匹配登记药品包和授权接收人，不能以任意机器人或任意包裹代替 | 事件对：`accepted` 与 `assigned` 的对象/角色映射；要求 package_id 一致、receiver_id 属于登记授权集合；身份集合大小建议 1 [待出题人裁决]。六类既有原语无法单独表达身份等式，需出题人决定是否作为附加检查 |
| 5 | `medication_handoff_complete_within_horizon` | 截止期（deadline，新原语提案） | 全链条在任务窗口内完成，避免无限等待接收 | 终点=`closed`；horizon=8500 拍（170 秒）[待出题人裁决]；超时为任务未完成，不把它改写成身份或顺序违约 |

V2 计分说明：#1/#2 的先后违约走 D3 义务分，违规不打断实验；#3 资源违规走 D3；#4 是结果身份检查，若确认需要独立计分须在合同版本中登记；#5 是任务成功条件。`quarantine_marked` 的新增必须与共同锚点组同步进入新合同版本并重新走绑定流程。

## 7. 难度与设计意图

- 主要考察药品对象、检查状态和责任身份的连续保持：检查记录必须落到同一包裹，标记不能脱离检查，释放不能绕过隔离，授权接收不能被任意机器人或“已发送消息”替代。
- 预期失败模式包括：跳过相机检查直接标记、把条码读取当作隔离完成、隔离位未释放就放入第二包、把包裹放在交接位附近当作接受、接收者身份不匹配、链账本没有闭合。
- D1 检查首次计划是否包含检查→标记→释放→接收的必要链和所需能力；D2/D3 由外部事件、身份和隔离资源记录评估；D4 可登记检查或条码能力失效变体，但必须保留共享公共历史和剩余工作可行性；D5 可作为 C-P2-02 跨域候选，需另行认证，不因同名任务自动成立；D6 记录完成任务的通信量和物理时间。
- 本锚点没有默认故意不可行材料。若实例因无合格检查能力、无授权接收人或隔离位不可达而物理不可行，应在运行前标记 D1 不可行并要求安全拒绝；不能在事后删除必需义务。
