# 锚点底稿：prod-p1-02（仓库 · 双货架补货与独立核验，P1）

- anchor_id：prod-p1-02
- 域 / 场景：production / warehouse_nvd
- scene_anchor：`warehouse_putaway_and_audit`；关系签名：P1；common `C-P1-02` 生产域成员
- 目标：补齐两排货架，同时由另一台机器人独立核验标签和数量
- 时间范围（horizon）：140 秒（7000 拍）[待出题人裁决]
- 难度向量（目录骨架建议值，八项均 `[待出题人裁决]`）：依赖深度 1、协调宽度 1、能力稀缺性 1、竞争度 0、危害级 0、通信需求 1、分支负荷 1、不确定性 0

## 1. 任务故事

仓库收到两批独立补货单，补货员分别把物料放入货架 A、货架 B，并使货位状态可由外部观察核对。第二台机器人在补货过程中独立读取标签与数量，形成核验记录；核验机器人不得把“收到补货消息”当成核验完成。两排货架可在路线和物料资源允许时并行处理，核验结果须在两排补货实际完成后汇总。任务在时间范围内完成，漏放、错货和只报告完成均不算终局成功。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| replenish_shelf_a | 取用 A 批物料，运至 A 货架并完成正确货位放置 | 与 `replenish_shelf_b` 可并行 |
| replenish_shelf_b | 取用 B 批物料，运至 B 货架并完成正确货位放置 | 与 A 独立；共享资源时按实际占用排程 |
| verify_labels | 对两排货架的标签、数量和目标货位逐项读取并形成外部记录 | 读取可与补货交错；汇总在两项补货完成后 |

## 3. 角色与能力

- 角色：`replenisher`（补货执行）、`auditor`（标签与数量核验）；由系统按能力动态分配。
- 必需能力：`mobile_base`、`barcode_scan`；如场景要求搬运离地物料，`payload_transport` 为待绑定能力项。
- 货架和物料身份由场景/评估器注册，不预设机器人型号或固定身份。

## 4. 里程碑（外部可观测定义）

| 标签 | 可观测定义 |
| --- | --- |
| assigned | 任务与两批物料、目标货架和核验范围写入评估器账本。 |
| both_shelves_replenished | A、B 两批末件均在正确货位放置并由外部物料状态确认。 |
| labels_verified | 两排货架的标签和数量均有有效扫描/观察记录，记录关联具体货位。 |
| accepted | 补货、核验和截止期条件同时满足，评估器写入终局验收事件。 |

## 5. 资源与区域

| 资源 | 建议命名 | 位置描述 | 容量/互斥 |
| --- | --- | --- | --- |
| A 货架 | `shelf_a` | 仓库主通道一侧的第一排货架及其前沿作业带，边界待语义地图对齐 | 货位集合与 A 批物料一一对应；占用容量待定 [待出题人裁决] |
| B 货架 | `shelf_b` | 与 A 货架相邻但可独立接近的第二排货架前沿作业带 | 同上；若共享通道形成竞争，互斥范围待定 [待出题人裁决] |
| 物料车 | `stock_cart_a`、`stock_cart_b` | 各货架附近的补货车/暂存位；[待绑定：确认两批物料容器及位置] | 每批一辆的建议配置；是否共享容量待定 [待出题人裁决] |
| 核验观察区 | `audit_zone` | 能同时看到两排货架标签的通道或货架端头 | 不作为系统提示接口；评估器按外部扫描位置记录 |

任务描述可公开“两排货架是独立补货目标，核验需读取标签和数量”；不公开评估器账本或未来物料位置。
上述资源均为候选语义绑定；`warehouse_nvd` 与 30 场景任务卡没有可据此冻结的唯一资产映射，需由语义地图和接口核验后登记。

## 7. 难度与设计意图

考察补货和独立核验之间的并行安排、物料身份核对与结果汇合。预期失败包括只补一排、标签扫描脱离真实货位、核验早于放置、两项工作无故串行导致超时。D1 只对预注册且带可检查不可行证明的变体要求安全拒绝；地图、接口或评估记录未知属于待绑定/评估器不足，不能以“安全拒绝”计分。D3 按目录义务二值计分，同一物料车占用事实不因多种表述重复扣分。
