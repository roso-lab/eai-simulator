# 锚点底稿：prod-p2-02（仓库 · 质检至隔离位的监管交接，P2）

- anchor_id：prod-p2-02
- 域 / 场景：production / warehouse_nvd
- scene_anchor：`inspection_to_quarantine_handoff`；关系签名：P2；common `C-P2-02` 生产域成员
- 目标：把已检查包裹交给隔离操作员并保存监管链
- 时间范围（horizon）：170 秒（8500 拍）[待出题人裁决]
- 难度向量（目录骨架建议值，八项均 `[待出题人裁决]`）：依赖深度 2、协调宽度 1、能力稀缺性 2、竞争度 1、危害级 1、通信需求 2、分支负荷 1、不确定性 1

## 1. 任务故事

检查员在仓库扫码并检查包裹，确认结果后将包裹放入隔离位并完成隔离标记。隔离操作员接收同一包裹的监管责任，形成可追踪的释放和接收事件。隔离位一次只能容纳一个有效占用者；包裹放下后仍属于隔离占用，不能因机器人离开就立即忽略。该锚点与服务域姊妹及 `liv-p2-02` 共享 `quarantine_marked` 里程碑语义，最终版本需同步登记。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| inspect_package | 扫描包裹身份并完成登记检查 | 先于标记 |
| mark_quarantine | 将同一包裹置于隔离位并完成外部可见隔离标记 | 严格晚于检查 |
| accept_chain_of_custody | 隔离操作员确认包裹与监管责任接收 | 严格晚于释放 |

## 3. 角色与能力

- 角色：`inspector`、`quarantine_operator`。
- 必需能力：`mobile_base`、`barcode_scan`、`inspection_camera`；搬运包裹所需 `payload_transport` 待场景确认。
- 身份映射以包裹条码、隔离位状态和实际机器人观测为准，不预设角色机体。

## 4. 里程碑（外部可观测定义）

| 标签 | 可观测定义 |
| --- | --- |
| assigned | 包裹身份、检查项目、隔离位和接收责任写入账本。 |
| inspection_complete | 条码与检查图像/结果已由评估器从观测记录确认。 |
| quarantine_marked | 包裹实际进入隔离位且隔离标记动作/状态外部可见。 |
| released | 外部监管账本记录检查员释放该包裹责任；与机器人/包裹物理退出隔离位分别观测。 |
| accepted | 隔离操作员对同一包裹完成接收并登记监管链。 |
| closed | 监管链记录完整且终局验收事件产生。 |

## 5. 资源与区域

| 资源 | 建议命名 | 位置描述 | 容量/互斥 |
| --- | --- | --- | --- |
| 质检台 | `inspection_station` | 仓库质检通道内带扫码与相机的工作台 | 一次处理一件包裹的建议值 [待出题人裁决] |
| 隔离位 | `quarantine_bay` | 质检台旁侧有边界标记的隔离存放区域 | 容量 1；机器人在位或其放置包裹占用时均算占用 [待出题人裁决] |
| 监管交接面 | `custody_receipt_face` | 隔离位外沿供接收员核对条码和状态的区域；[场景缺口：需确认接收面] | 单包裹责任接收 |

任务描述可声明隔离位一次只能处理一个包裹；不向被测系统提供评估器位置账本或内部占用接口。
质检台、隔离位和接收面均为候选绑定，尚不据旧 `scene_key` 断言资产或交互接口已经存在。

## 7. 难度与设计意图

考察检查结果、隔离状态和责任接收的链条一致性。预期失败包括未检查即标记、放下包裹后错误释放隔离位、接收消息无物理包裹、两包裹重叠占用。D1 安全拒绝仅适用于预注册并具有可检查不可行证明的变体；隔离位或身份接口未知属于待绑定/评估器不足。D3 按义务计分，隔离位的同一占用事实只计一次。
