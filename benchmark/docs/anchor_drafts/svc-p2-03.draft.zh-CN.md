# 锚点底稿：svc-p2-03（仓库 · 限时服务请求转移，P2）

- anchor_id：svc-p2-03
- 域 / 场景：service / warehouse_nvd
- scene_anchor：`urgent_service_queue_transfer`；关系签名：P2；common `C-P2-03` 服务域成员
- 目标：在截止期前转移等待中的服务请求并记录负责响应方
- 时间范围（horizon）：180 秒（9000 拍）[待出题人裁决]
- 难度向量（目录骨架建议值，八项均 `[待出题人裁决]`）：依赖深度 2、协调宽度 2、能力稀缺性 1、竞争度 2、危害级 1、通信需求 2、分支负荷 2、不确定性 1

## 1. 任务故事

仓库服务队列中有一项等待请求，源端机器人确认请求身份、位置和紧急截止期后，将其放入待处理状态。响应机器人在发运/服务通道接收请求并继续处理，形成可追踪责任链。请求必须在截止期前接收，单一通道一次只能服务一项请求。只发送队列消息、响应端到达附近或把请求留在等待区均不算完成。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| stage_order | 确认请求并在等待区登记身份、目标和截止期 | 先于释放 |
| release_order | 源端将请求责任从等待区释放 | 先于接收 |
| accept_dispatch | 响应端接收请求并实际开始后续服务 | 严格晚于释放，且在截止期前 |

## 3. 角色与能力

- 角色：`stager`、`dispatcher`。
- 必需能力：`mobile_base`、`payload_transport` 或等价服务搬运能力；`service_interaction` 为待绑定项。

## 4. 里程碑（外部可观测定义）

| 标签 | 可观测定义 |
| --- | --- |
| assigned | 请求身份、服务目标、通道和截止期写入账本。 |
| staged | 请求在指定等待区且身份/截止期可核对。 |
| released | 请求责任离开源端并形成释放事件。 |
| accepted | 响应端在服务通道实际接收同一请求并开始处理。 |
| closed | 请求接收、后续服务和截止期条件均满足。 |

## 7. 难度与设计意图

本题把服务队列的限时接续、责任交接与通道互斥结合起来。预期失败包括错请求、消息先接收、通道拥堵死锁和过截止期才处理。D4 可登记通信/交互失效变体，但保留原截止期和原因码。
