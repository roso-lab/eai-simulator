# 锚点底稿：svc-p1-02（餐厅 · 两就餐区复位与独立审计，P1）

- anchor_id：svc-p1-02
- 域 / 场景：service / restaurant
- scene_anchor：`table_reset_and_audit`；关系签名：P1；common `C-P1-02` 服务域成员
- 目标：并行复位两个就餐区，并独立检查用品与服务记录
- 时间范围（horizon）：140 秒（7000 拍）[待出题人裁决]
- 难度向量（目录骨架建议值，八项均 `[待出题人裁决]`）：依赖深度 1、协调宽度 1、能力稀缺性 1、竞争度 0、危害级 0、通信需求 1、分支负荷 1、不确定性 0

## 1. 任务故事

餐厅闭台后需要把就餐区 A、B 的桌面和用品恢复到登记状态。补给/复位机器人分别完成两个区域，审计机器人读取用品标签和服务记录，确认每区状态。两个区域可以并行，但共享通道或餐车冲突时按外部占用排程。最终验收要求两个区域和审计记录均正确，不能以“桌面看起来整齐”替代物品核验。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| replenish_shelf_a | 复位 A 区桌面、座位和登记用品 | 与 B 可并行 |
| replenish_shelf_b | 复位 B 区桌面、座位和登记用品 | 与 A 可并行 |
| verify_labels | 读取两区用品标签和服务记录并形成核验结果 | 两区外部完成后汇总 |

## 3. 角色与能力

- 角色：`replenisher`、`auditor`。
- 必需能力：`mobile_base`、`barcode_scan`；若需摆放物品，`payload_transport` 为待绑定能力。

## 6. 谓词清单（参数均待出题人裁决）

## 7. 难度与设计意图

本题考察多区域复位、用品身份核验和餐厅服务窗口下的并行安排。失败模式包括遗漏一桌、审计早于摆放、标签错配和复位消息代替外部状态。D6 可保留移动与通信成本，但不改变完成判定。
