# 锚点底稿：svc-p1-01（城市 · 两设施区巡逻与日志核验，P1）

- anchor_id：svc-p1-01
- 域 / 场景：service / city
- scene_anchor：`facility_patrol_and_log`；关系签名：P1；common `C-P1-01` 服务域成员
- 目标：巡逻两个独立设施区，同时由第二台机器人核验服务日志
- 时间范围（horizon）：120 秒（6000 拍）[待出题人裁决]
- 难度向量（目录骨架建议值，八项均 `[待出题人裁决]`）：依赖深度 0、协调宽度 0、能力稀缺性 0、竞争度 0、危害级 0、通信需求 0、分支负荷 0、不确定性 0

## 1. 任务故事

服务团队需要覆盖设施区 A、B 的登记巡逻范围，并在每区留下可核查的巡逻观察。第二台机器人独立读取设施标签和服务日志，核对区域、时间和记录身份。两项巡逻在路线和能力允许时可并行，最后在两区实际完成后汇总。机器人最终回到区域不能抵消中途漏巡或伪造日志。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| work_unit_a | 进入设施区 A，完成登记巡逻和外部观察记录 | 与 B 可并行 |
| work_unit_b | 进入设施区 B，完成登记巡逻和外部观察记录 | 与 A 可并行 |
| reconcile_units | 核对 A、B 的巡逻记录和日志身份，形成汇总 | 在两区完成后开始 |

## 3. 角色与能力

- 角色：`picker`、`counter`（可由系统复用机体）。
- 必需能力：`mobile_base`、`barcode_scan`；巡逻是否需要 `service_interaction` 待场景绑定。

## 7. 难度与设计意图

考察独立巡逻、日志身份核验和结果汇合。预期失败包括只巡一处、把最终位置当作全程覆盖、日志与区域错配、无故串行造成超时。执行期顺序违约进 D3；数据缺失区分 `unreached` 与 `evaluator_record_missing`。
