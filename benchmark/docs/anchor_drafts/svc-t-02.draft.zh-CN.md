# 锚点底稿：svc-t-02（城市 · 单一入口维修案交接与互斥，P2+P4）

- anchor_id：svc-t-02
- 域 / 场景：service / city
- scene_anchor：`maintenance_queue_with_handoff`；关系签名：P2、P4
- 目标：维修案经单一入口转移，并排除竞争工作同时进入
- 时间范围（horizon）：180 秒（9000 拍）[待出题人裁决]
- 难度向量（目录骨架建议值，八项均 `[待出题人裁决]`）：依赖深度 2、协调宽度 2、能力稀缺性 2、竞争度 2、危害级 1、通信需求 2、分支负荷 2、不确定性 1

## 1. 任务故事

城市维修案由案主机器人带到唯一的访问点。案主先占用访问点并释放维修案责任，响应机器人再在同一访问点接收并继续处理。访问点一次只能容纳一台相关机器人，其他竞争工作不得与该案重叠占用。释放与再进入按半开区间相接规则判断，任务需在时间范围内闭合。

## 2. 义务图

| 义务 | 内容 | 结构关系 |
| --- | --- | --- |
| reserve_access | 形成维修案使用访问点的排程/可观测占用准备 | 先于源端进入 |
| release_case | 案主在访问点完成状态移交并释放维修案责任 | 先于接收 |
| accept_case | 响应端接收同一维修案并继续工作 | 严格晚于释放 |
| release_access | 响应端完成后离开访问点并形成释放观测 | 终止访问点占用 |

## 3. 角色与能力

- 角色：`case_owner`、`responder`；竞争请求由评估器按实际轨迹识别。
- 必需能力：`mobile_base`、`service_interaction`；维修案读取能力待绑定。

## 4. 里程碑（外部可观测定义）

| 标签 | 可观测定义 |
| --- | --- |
| assigned | 维修案身份、访问点、响应责任和截止条件写入账本。 |
| reserved | 源端访问点占用准备可由外部占用记录确认。 |
| released | 责任账本记录案主释放维修案；不等同于访问点物理退出。 |
| accepted | 响应端在访问点实际接收同一维修案并开始处理。 |
| access_released | 响应端离开访问点，首个不占用拍写入账本。 |

## 7. 难度与设计意图

考察单一服务资源上的交接顺序、竞争排除和释放边界。失败模式包括两机重叠、接收先于释放、接收后不释放导致队列阻塞、消息代替实际处理。P4 资源条件与 P2 责任条件分别判定，避免重复计数。
