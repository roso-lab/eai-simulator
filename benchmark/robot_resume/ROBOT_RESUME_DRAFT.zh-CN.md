# 机器人简历草案 v0.1

本版供讨论和修改，尚未接入运行时。代码基线为 `HeteroCoord` 分支 `fcf593a9c6637278b6dbf0acb4f2cf54db2e836d`；2026-10-16 已执行 `git pull --ff-only origin HeteroCoord`，结果为最新。配套结构化样稿：[robot_resume_draft.v0.1.json](robot_resume_draft.v0.1.json)。

## 1. 这版简历的基本设计

**每个实际配置有自己的简历类型，每个参与任务的机器人实例有自己的简历。** 任务场景可以提供任意数量、任意合法组合的机器人，不预设固定四机队，也不预设每种型号只有一台。

例如 `Scout`、`Scout + UR5`、`Scout + Z1` 是三个不同配置，不能共用一份能力简历；`UR5 独立机械臂`也是可单独进入机器人池的机器人。两个相同配置的 Scout + UR5 可以复用能力模板，但各有独立 robot_id、位置、状态和持物记录。

`Scout + UR5` 作为一个组合机器人登记；它携带的同一条 UR5 不再重复占用一个独立机器人成员名额。独立 UR5 则单独登记，二者以实际安装关系区分。

建议将简历分成三个部分：

| 部分 | 内容 | 更新时机 |
| --- | --- | --- |
| 配置能力 | 平台、机械臂/夹具、传感器、控制器、技能和限制 | 配置或技能版本改变 |
| 实例状态 | 实例 ID、位置、可用性、当前持物和任务占用 | 按允许的观测与通信更新 |
| 简短描述 | 给 LLM 的身份、可用技能、关键参数和特殊说明 | 从前两部分生成 |

结构化信息保留完整约束，给 LLM 的文本突出影响任务分配的信息。Carter 可省略“不能上下楼”这一常识性说明；Lite3 必须明确写“**当前工程配置不具备上楼和下楼能力**”。省略文字不等于取消调度约束。

## 2. 建议交给算法的简历格式

```text
机器人：<robot_id>｜<平台及实际配置>
可用技能：<导航；抓取；放置；按实际绑定填写>
运动能力：<运动方式；需要强调的地形或楼层限制>
操作能力：<机械臂/夹具；载荷；相对机械臂基座的高度限制>
感知能力：<本实例已接通、且算法获准读取的传感器/观测>
特殊说明：<容易误判、配置特有、与当前任务相关的限制>
当前状态：<位置/楼层；可用/忙碌/备用/退出；持物；状态时间>
```

无关或不存在的段落可以省略。例如裸 Carter 不需要机械臂参数段，独立 UR5 不需要行驶速度段。未观测到的位置写“未知”，不能填原点。没有电量模型时不编造电量；没有测量时不编造速度、续航、坡度或爬楼高度。

文本中的“抓取”和“放置”对应同一个现有技能 `eai.manipulation.pick_place` 的 `pick`、`place` 操作；导航对应 `eai.navigation.node_route`。不新增虚构的 `pick`、`place` 或 `climb_stairs` 公共 skill ID。

## 3. 两种机械臂的限制

数值来自用户提供的 `manipulator_capabilities(1).json`（schema `eai.manipulator_capability`，版本 `3.0`），高度参考系由用户明确为**机械臂安装基座**。以下作为本工程的用户给定限制，不替换成网上产品参数，也不表述为本轮实测结果。

| 机械臂 | 载荷上限 | 最大抓放高度 z | 高度参考系 |
| --- | ---: | ---: | --- |
| UR5 | 5.0 kg | 0.824073 m | 该机械臂安装基座坐标系 |
| Z1 | 3.0 kg | 0.798026 m | 该机械臂安装基座坐标系 |

这些参数跟随机械臂配置，独立 UR5 和移动底盘上安装的 UR5 都引用 UR5 限制；整机部署若有更严格限制，最终使用更严格者。独立 UR5 固定在工作台或地面时，其安装基座世界位姿由本次场景提供，不能假定基座等于世界原点。

高度判定应使用实际机械臂安装位姿：`p_arm = R_world_armᵀ × (p_world − t_world_arm)`，比较其中的 z。只有基座轴线与世界轴线对齐时，才能简化成世界高度减安装高度；不能直接拿世界 z 或底盘相对 z 与表内限值比较。

这两个高度值不是完整可达空间。水平半径、最小高度、姿态、障碍和抬升/回收路径仍需后端检查。当前抓放接口的目标坐标是物体原点，而上传文件未定义该高度上限针对物体原点、抓取点还是末端点；结构化样稿保留 `limit_point: null`，后续确认后再落实自动判定。载荷是否包含工具自重也保留为待明确的计量口径，不擅自换算。

## 4. 可直接修改的简历示例

以下 ID 仅用于展示，机器人数量和组合不固定。示例中的技能文字表示**对应部署及后端绑定确认后的简历写法**，不证明当前有这些活动实例；配套 JSON 均保留待绑定状态。

### 4.1 Carter，无外接机械臂

> **carter_01｜Carter 移动底盘**  
> 可用技能：导航至本机器人地图中的指定节点。  
> 运动能力：差速轮式移动。  
> 配置：未安装机械臂，不承担抓取和放置任务。  
> 感知与当前状态：由本次部署及公开观测填入。

默认不展开楼梯限制。若当前任务确实要求通过楼梯，资格检查应直接排除不具备该能力的配置，并在拒绝原因中说明。

### 4.2 Lite3，无外接机械臂

> **lite3_01｜Lite3 四足机器人**  
> 可用技能：在已配置可通行区域内导航。  
> 配置：未安装机械臂，不承担抓取和放置任务。  
> **特殊说明：当前工程配置不能上楼，也不能下楼。不能因其四足形态而分配楼梯通行任务。**  
> 感知与当前状态：由本次部署及公开观测填入。

该限制来自用户对本工程的明确设定，不泛化成所有 Lite3 硬件的普遍结论。若后续支持其他 Lite3 配置，应另行确认，而不是自动改变本模板。

### 4.3 Scout，无外接机械臂

> **scout_01｜Scout 移动底盘**  
> 可用技能：导航至本机器人地图中的指定节点。  
> 运动能力：差速轮式移动。  
> 配置：未安装机械臂，不承担抓取和放置任务。  
> 感知与当前状态：由本次部署及公开观测填入。

### 4.4 Scout + UR5

> **scout_ur5_01｜Scout 移动底盘 + UR5 机械臂及夹具**  
> 可用技能：导航、局部抓取、局部放置；各技能由本实例实际绑定提供。  
> 操作限制：UR5 载荷上限 **5 kg**；最大抓放高度 **0.824073 m，相对机械臂安装基座**。  
> 特殊说明：先到达操作位置，再执行局部抓取或放置；当前简历不声明边走边操作或任意物体姿态控制。持物导航须单独获得本配置的支持，不能由“会导航＋会抓取”自动推出。  
> 感知与当前状态：由本次部署及公开观测填入。

裸 Scout 与此配置是不同的能力档案。如果它们同时出现在任务池中，应对应两台不同实例。带臂版本的通行尺寸、运动能力、稳定性和可达范围都按实际配置记录。

### 4.5 M20 + Z1

> **m20_z1_01｜M20 轮腿机器人 + Z1 机械臂及夹具**  
> 可用技能：本配置已绑定的导航、局部抓取和局部放置。  
> 操作限制：Z1 载荷上限 **3 kg**；最大抓放高度 **0.798026 m，相对机械臂安装基座**。  
> 特殊说明：带臂配置的上下楼能力需要独立确认，不沿用裸 M20 的推断。未确认时不承担楼梯通行或持物跨楼层任务。  
> 感知与当前状态：由本次部署及公开观测填入。

### 4.6 独立 UR5

> **ur5_station_01｜独立固定基座 UR5 机械臂及夹具**  
> 可用技能：工作范围内的局部抓取和局部放置。  
> 操作限制：载荷上限 **5 kg**；最大抓放高度 **0.824073 m，相对该 UR5 安装基座**。  
> **特殊说明：没有移动底盘，不能自行导航或前往其他操作位置。物体与放置目标必须位于本站实际可达范围内。**  
> 当前状态：安装位姿、可用性和持物情况由本次场景提供。

独立 UR5 自己占一个 robot_id，是完整的可调度机器人；不会被登记成另一台机器人的附件。“抓取后在本站范围内放置”不等同于能跨场景搬运。

### 4.7 G1，当前固定基座抓放配置

> **g1_station_01｜G1 固定基座操作配置**  
> 可用技能：已标定物体的局部抓取和局部放置。  
> **特殊说明：此配置不提供行走，限当前后端支持的直立轴向物体与标定范围，不支持任意物体姿态。**  
> 载荷和高度：使用 G1 本身的配置数据，不能套用 UR5/Z1 参数。  
> 当前状态：由本次部署及公开观测填入。

G1 行走配置应是另一份简历，不能把不同后端的能力无条件合并成“会走路且会任意抓放”。

## 5. 当前机器人库的首版描述规则

以下覆盖当前 catalog 中的 14 类平台，并补充用户明确的独立 UR5。它是模板目录，实际任务只发送本次池中的实例。

| 平台/配置 | 简历主要描述 | 应特别说明的内容 |
| --- | --- | --- |
| Carter | 差速移动；按附件形成不同简历 | 带臂时给出机械臂限制；裸机无需默认展开楼梯常识 |
| SimpleCar | 平面移动；按实际控制接口描述 | 不从 planar 名称推导所有接口均支持横移；当前 ROS cmd_vel 路径不保留横向速度 |
| Scout | 差速移动；裸机/UR5/Z1 分开 | 持物行驶和边走边操作不是自动具备 |
| MuSHR v2 | Ackermann 车式转向 | 不描述为可横移或原地旋转；需要满足本控制器转向约束 |
| Coco | Ackermann 车式转向 | 同上，地图可达性必须匹配实际转向能力 |
| Go2 | 四足移动；带臂独立配置 | 普通配置与楼梯控制器配置分开；上楼、下楼分别确认 |
| B2 | 四足移动；带臂独立配置 | 不复用 Go2 参数；楼梯能力按本配置确认 |
| M20 | 轮腿移动；带臂独立配置 | 不能由轮腿形态直接宣称已具备上下楼能力 |
| Lite3 | 四足移动 | **明确不能上楼、不能下楼** |
| Pepper | 全向底盘；可有原生双臂抓放配置 | 原生双臂不属于 UR5/Z1；抓放需要对应后端，当前不控制任意物体姿态 |
| G1 | 行走配置或固定基座抓放配置 | 后两者的能力不能直接合并；固定操作配置必须明确不能行走 |
| CF2X | 空中节点导航，前提是控制器适配已绑定 | 不由飞行能力推导抓放能力；当前统一无人机抓放后端未列 CF2X |
| Iris | 空中节点导航；匹配位置控制器时可绑定局部抓放 | 挂接搬运机制和控制器条件应明确；载荷与飞行包线不套用机械臂参数 |
| Pegasus/X4 | 同上，使用本机实际控制器和绑定 | 旋翼控制配置不自动等于局部抓放所需的位置控制配置 |
| 独立 UR5 | 固定工作站内抓取/放置 | **不能自行导航**；需实际夹具、安装位姿和可达范围 |

传感器也从实际实例读入，不把“该平台支持安装”写成“本实例已拥有”。没有外接机械臂不代表没有操作能力：独立 UR5 的机械臂是主体，Pepper/G1 的机械臂是原生结构。

## 6. 带臂配置与现有部署记录的关系

用户文件规定机械臂参数；它本身不改变宿主挂载适配的既有状态。当前 catalog 对 UR5/Z1 的未缩放静止挂载记录如下，**这些是现有工程记录，不是本轮重新测试结果**：

| 底盘 | + UR5 | + Z1 |
| --- | --- | --- |
| Carter | 当前挂载记录拒绝 | 静止测试条件通过 |
| Scout | 静止测试条件通过 | 静止测试条件通过 |
| Go2 | 当前挂载记录拒绝 | 静止测试条件通过 |
| B2 | 静止测试条件通过 | 静止测试条件通过 |
| M20 | 当前挂载记录拒绝 | 静止测试条件通过 |
| Lite3 | 当前挂载记录拒绝 | 当前挂载记录拒绝 |

“条件通过”不表示带臂运动、持物运输或真实接触抓取都已验证；“拒绝”也不表示该机器人型号永久不能携带该机械臂，结论针对已有挂点、资产和控制组合。后续若调整配置或明确采用另一种仿真操作模式，应生成新的配置记录与相应简历。

工程当前统一 ArmPickPlaceAdapter 使用 idealized manipulation runtime；物理接触抓取的既有组件证据与该模式分开记录。给算法的简历可以描述当前仿真提供的操作能力，但实验记录需保留执行模式，避免把仿真挂接成功写成硬件接触抓取认证。

catalog 还有 `ur5_bare`。仅有裸臂、未装夹具时，不自动发布抓取/放置能力，也不等同于本草案中的“UR5 及夹具”。独立 UR5 的资产/固定底座验证入口已经存在，但尚未作为 Env DIY 的 `ROBOT_KEYS` 顶层类型；这是后续接入点，不妨碍本设计将其作为独立机器人。

## 7. 机器人池与动态变化

组池时先选择实际配置，再生成实例：

```text
配置库：Carter / Scout / Scout+UR5 / M20+Z1 / 独立UR5 / …
        ↓ 本次任意选择、允许同配置多实例
实例池：robot_id + configuration_id + 初始位姿 + 初始可用性
        ↓ 验证实际部署、技能绑定、地图与特殊限制
公开简历快照：本次可见的成员及其能力/状态
        ↓
任务分配、导航、局部抓放、反馈与重分配
```

每次任务可以有不同机器人池；同一比较实验及其配对分支仍应固定初始池与配置。空闲成员开始工作不算“加入”；备用成员成为活动成员才改变成员状态。当前 fleet 加入实现限于预登记 inactive reserve，任意新实例的热加入属于后续扩展。

退出时保留历史简历供追溯，并从可分配候选中移除；技能故障只禁用受影响技能，不重写型号固有属性。装卸机械臂改变 configuration_id 和简历版本，应重新确认受影响的技能、地图及运动能力。同一物理机器人不能同时以裸机和带臂两个可用 ID 重复出现在池里。

位置、忙闲、持物和故障信息按论文/协议允许的观测与通信传播；不在全局简历中泄露尚未获知的动态状态。保留 snapshot/version/generation，避免重配置后继续使用旧简历下发动作。

## 8. 与当前工程的接入位置

| 内容 | 现有基础 | 后续衔接 |
| --- | --- | --- |
| 配置事实 | robot_dossier、capability_profile、Env DIY catalog | 纳入用户机械臂限制、原生/外挂/独立操作结构与实际安装外参 |
| 已绑定技能 | NavigationExecutor / PickPlaceExecutor 的 robot_id 适配器 | 输出本实例可用技能与后端条件，不照抄全局 registry |
| EMOS 输入 | resume_provider、RobotProfileSpec、讨论文本 | 从统一公开档案生成，替换固定名字推断；特殊说明始终保留 |
| benchmark roster | RuntimeTaskBinding、RobotCapability | 按配置与实例显式绑定，取消未验证的列表顺序能力继承 |
| 动态状态 | FleetRuntime | 将成员和功能事件投影到允许公开的简历快照 |
| 楼梯资格 | 本草案的 stair_ascent / stair_descent | 在绑定机器人专属地图时筛除不可通行边；任务资格检查同步使用 |

特别是最新 node_route 的地面路径按 XY 工作，NavigationProfile 当前只有几何度量、到达半径与终点朝向支持，未实现本草案的楼梯能力过滤。因此只在文字里写“Lite3 不能上下楼”还不足以约束执行；后续必须让每机器人地图/资格检查使用同一限制。存在 Go2/B2 楼梯控制器选项，也不能单凭控制器名称就把所有楼梯标为可通行。

## 9. 本版已经确定与留待修改的内容

已经按用户要求确定：机器人池不固定；有臂/无臂为不同配置简历；UR5 可作为独立机器人；UR5 5 kg、Z1 3 kg；两者高度上限分别为 0.824073 m、0.798026 m，均相对机械臂安装基座；Lite3 明确不能上下楼；Carter 默认简短描述可省略楼梯常识。

留待修改：其他配置上下楼的具体支持范围；机械臂高度限制对应的目标点及载荷计量口径；各配置的持物导航支持；需要向 LLM 展示多少感知和状态细节。草案未提供证据的数值保持未知，不补全推测。

本轮只新增设计文档和 JSON 样稿，未改写运行时或替换现有 EMOS 简历。
