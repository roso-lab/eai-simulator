# 通用实验运行架构开发清单

本清单只管理与正式实验任务无关的基础设施。正式任务、任务合同、干预语义、
业务成功谓词和论文指标由任务设计方提供，不在这里另建版本。
复用现有 `EaiTaskPackage`、`SkillRequest/SkillPlan`、`ExecutionUpdate` 接口；
新增的运行适配器不改变 `simulator.skill.v1`。临时场景与诊断产物只放 `tmp/`。

## 第一阶段：单 session 通用执行闭环

- [x] 明确任务设计与运行基础设施的所有权，保留已有 task/skill 合同。
- [x] 提供可注入的 live observation 采样，在初始规划、执行前、执行后和重规划时
  校验 scene、revision 和 tick，拒绝过期或身份不匹配的状态。
- [x] 实现 session 内共享资源租约：原子申请、冲突拒绝、幂等释放、异常隔离；
  无法确认停止的执行保留资源占用，不能在异常 finally 中盲目释放。
- [x] 实现通用 `Assignment → SkillRequest → provider → runtime → ExecutionUpdate`
  执行器；业务请求映射和物体资源绑定由调用方注入，禁止猜测任务 metadata。
- [x] 将执行反馈接回现有有界 DAG/replan，重规划读取最新机器人状态与世界观测。
- [x] 验证成功、资源竞争、能力变化、请求/反馈身份不匹配、失败后显式重试、
  停止失败、重复请求和无 evaluator 时 N/A；测试不推断物理成功。
- [x] 更新运行接入说明与验收记录。

第一阶段验收（2026-10-11）：task 单元/集成 58 passed；含既有 skill、tool、回放字段
和方法注册的扩展回归 174 passed、1 skipped（未安装的历史外部场景插件）。
独立代码审查提出的六项问题已修复并加入回归。真实 Isaac GPU 临时诊断完成
一次注入的动作前失败、显式重试及两个依赖执行窗口，共 120 个物理步；任务资源
和 GPU 租约归零，外部 evaluator 验证 1.5 kg 刚体稳定支撑，离线 validate 通过。
它验证通用运行接线，不代表 Pepper 搬运、实际机器人故障、正式任务或并发认证。

## 第二阶段：真实 runtime 接入与执行控制

- [x] 在不定义正式任务的前提下，为现有 Pepper skill 接入通用执行器做临时 Isaac
  验证；检查请求目标与实际 controller 绑定，不能把不同请求执行成同一预设流程。
- [x] 统一导航 skill provider/runtime 接口，沿用既有规划与控制器实现。
- [x] 在单一仿真步进所有者下实现可协作推进的 skill handle、取消与安全停止；
  验证同场景多机器人动作合并，不能把串行 batch 称为同步物理执行。
- [x] 将占用资源、持物状态、skill 状态机接入已有 checkpoint component 系统，
  明确资源恢复与实际物理状态的对账顺序。

第二阶段验收（2026-10-11）：8 kg 箱体 small (.22,.24,.24)、nominal (.26,.28,.30)、
large (.28,.32,.34) 的 Isaac GPU 临时搬运验证；阶段截图已实际查看。两台 Pepper
同场景共享 240 ticks 完成导航，另测在 tick80 请求取消、tick130 全体停止。
持箱取消沿原路线安全放置并报告调度失败；不是即时急停。最终默认停止探针检查
底盘、双臂和箱体速度，未确认则隔离整个共享 scene。
small/large 持箱阶段回退通过关节/刚体/目标读回（误差0），之后完成搬运。
checkpoint 范围严格限定同一 live handle、原始未释放租约；不回退 scheduler 记录，
不支持跨进程任务续跑或 PhysX 隐藏状态/轨迹等价声明。大箱体释放后可能转为另一面
落桌；现有 evaluator 的稳定支撑通过不意味着满足尚未定义的“保持直立”谓词。

## 第三阶段：运行可靠性与复现

- [x] 隔离进程 supervisor 与跨进程 GPU 准入，验证 1→2→4 容量与隔离效果。
- [x] 硬超时 watchdog、工作进程异常退出和显式新运行恢复；保全原始未封存记录。
- [x] 扩展声明依赖指纹到资产、controller、模型和外部输入；不同指纹禁止续跑。
- [x] 建立分层验证命令：纯逻辑回归、临时 Isaac 接入、故障注入、视觉证据。

第三阶段容量实测：同卡轻量 plane+Pepper，1/2/4 独立 Isaac 进程同时驻留
7.25/9.67/14.84秒，整卡显存峰值3983/7284/13886MiB；每进程120物理步。
这是该场景容量记录，不是复杂正式场景、显存硬隔离或32路认证。隔离边界要求
worker 保持前台进程组及继承准入FD；外部不使用同一准入目录的程序不受约束。
用法见 [进程与复现说明](../tools/benchmark_branch/PROCESS_RUNTIME.zh-CN.md)。

真实故障注入：Isaac 完成初始化后故意忽略TERM并挂起，65秒watchdog升级KILL，
返回-9、进程组确认终止；另一轮初始化后退出17；第三轮用同一slot新attempt成功，
原始ready/log/receipt文件均保留。不把强杀当成物理安全停止，也不续接旧任务状态。

最终扩展回归234 passed、1 skipped；编译与diff检查通过。当前机器完整诊断记录位于
`tmp/cooperative_runtime/VALIDATION.md`（含未通过的首次试验、修正原因、截图、
真实命令和重跑入口），runtime结果按约定不加入Git。

## 第四阶段：连续执行与中断边界加固

- [x] 禁止失败/未推进 tick 调用 after_step，避免旧观测累计为停止证据。
- [x] 动作构造失败不提交部分动作；取消尝试在持续失败时仍有上限。
- [x] 回调内隔离优先于回执和下一次共享 step，覆盖同场景其他机器人。
- [x] Ctrl+C/SystemExit 原异常继续抛出；已启动租约隔离、未启动租约释放。
- [x] 增加 admission/validate/start/command/step/poll/cancel 的故障回归。
- [x] 真实 Isaac Pepper 持箱 step 回调故障注入、阶段截图检查与最终扩展回归。

第四阶段验收（2026-10-11）：新增19项故障回归，扩展结果253 passed、1 skipped；
编译与diff检查通过。真实Isaac GPU/GUI中，在nominal 8 kg箱体持物移动的第261步
完成物理推进后注入回调异常；第666步确认完成安全放置，handle仅采样665次。
调度保持retryable_failure，独立物理evaluator确认稳定支撑，gate关闭、租约归零；
已查看持箱/最终放置阶段截图。该测试验证Python回调故障后的有界排空，不代表
PhysX内部故障也可恢复、即时急停或正式实验任务成功。

首轮GUI物理验证完成，但逐扩展卸载时进程SIGSEGV(-11)，不计完整进程通过。
同配置headless复跑674步并正常退出0；GUI使用Isaac默认快速退出选项复跑667步，
同样退出0、进程组完全终止，最终放置截图已检查。快速退出避开了逐扩展卸载路径，
并非已修复Kit内部退出缺陷。该遗留问题在第五阶段完成修复与完整退出复验。
完整日志及GUI复核命令见上述tmp验证记录。

## 第五阶段：主分支兼容与失败路径审查

- [x] 拉取 HeteroCoord，保留地面导航 provider 和拓扑创作工具的接口与文档。
- [x] 完整 SkillRequest 字段纳入防篡改摘要，执行前检查任务身份、版本和运行绑定。
- [x] 串行执行器从资源申请后的日志/校验开始保护租约，外部隔离优先于成功回执。
- [x] 协作启动回调隔离整场景后，未启动的同批任务返回 SAFE_STOP，保留隔离租约。
- [x] 恢复写入被中断时执行所有失败钩子；失败报告写盘不能阻止隔离或覆盖原异常。
- [x] GUI 截图接口及时释放；会话仅为自己创建的应用执行退出清理。
- [x] 完整 GUI 搬运与逐扩展退出验收，完成提交前独立审查。

本阶段最终扩展回归375 passed、1 skipped，编译及diff检查通过。真实GUI最终版本
使用完整逐扩展关闭（fast_shutdown=False），159.73秒正常退出0，进程组完全终止。
nominal 8kg箱体在第261步持箱推进后注入回调失败，并回退24个handle ticks；
第691步结束、handle采样666次，读回误差0，独立物理evaluator通过、gate关闭、租约归零。
调度保留retryable_failure，未将排空后的放置成功伪报为正常执行成功；已实际查看
持箱及最终落桌截图。相同核心修复的前一轮也完整退出0，所有失败尝试保留在tmp。

修复包含Kit107菜单hook/窗口回调释放、菜单服务停止和PhysX共享view的native owner
及时释放。只处理session自身创建的应用，不修改已安装SDK；环境关闭时先捕获view，
防止STOP清空全局引用后漏掉回放或controller持有的对象。失败路径经过独立审查。
自建额外PhysX view仍需由其拥有者显式关闭；未对未启用的NativePhysicsTrace做退出认证。
