## 1. 发布目标与当前结论

目标仍是五场景完整 **5×9×9=405 个条件题包、315 个单因子对照对**。
这是45个场景/变体身份的条件展开，不是405个独立业务任务，也不是405次原生通过。
阶段34已完成生成、读回与双机检查；当前不需要继续扩题量来替代执行闭环。

工程方向应收敛为：**自主决策与执行 → 可信物理/业务事件 → 可离线复算的测量 →
有适用范围的实验结论 → 单场景发布认证**。目前题包、通信、部署门禁、审计等组件
已有较多实现，但还不能称为五场景可打分 Benchmark。餐厅七技能原生成功证明了
特定诊断路径；阶段37双机各273项通过证明了同组组件回归，均不证明自主执行已闭环。

发布认证单位是一个场景 registration；五场景总审计是总览，不设“一处资产失败
阻塞全部开发”的全局死锁。可逐场景交付候选证据，但不得把部分认证宣称为405格
全量正式发布，或静默删掉不支持的机器人、条件和失败样本。

```yaml
scoreable: false
execution_validated: false
business_outcomes_validated: false
```

以上保持不变。本路线图不授权翻转标志；正式晋级还需独立、版本化的原生证据验收。

## 2. 对推进方式的反思

1. **先测高层能力，再补必要的执行保真。** 抓取允许按既定技能契约理想化；保留负载、
   占用、可达性和可信业务结果，不继续为与协作结论无关的精细IK/接触调参无限投入。
   若底层故障会系统性惩罚某类分配，则是平台有效性问题，必须修复或明确阻断该条件。
2. **测试程序不能变成标准解法。** 模型自行拆题、选人和排时序；见证只证明一种路径，
   不能限定成员互异、固定任务顺序、只观察一次、必须启用某工具或固定协作人数。
   环境真实前置条件仍需检查。至少用两种合法策略验收接口自由度，而非要求模型复刻作者。
   能力/运动匹配错误按既定接口记为执行结果，不新增计划阶段的能力资格处罚；已有结构、
   资源和预算准入规则保持其明确边界。
3. **按声明的机会测能力。** 单机合法解应保留；只有真实存在依赖、重叠服务或交接窗口，
   才支持耦合协调测量。机制名称、机器人数量或干预配置存在，不等于处理实际生效。
4. **部署判断针对剩余可达性。** 木箱已到dock后失去抓取者，不应因“回执里程碑未关”
   判不可行。oracle依据当前可信状态、剩余硬终局谓词和可用资源；不能对照见证步骤。
   在预注册测量点认证有限任务抽象的判定边界，不承诺求解任意PhysX状态的通用可达性。
5. **平台失败与模型失败分开。** 缺驱动不能伪造member_exit；基础设施失败不能计作模型
   正确求助。oracle证据失败是质量故障，不是第三种模型答案，也不得根据模型成绩事后剔除。
6. **门禁对应具体结论。** native restore/sham阻挡严格同快照分支结论；不阻挡无分支
   执行、原始数据生产和普通实验开发。组件测试数量不能替代真实事件源接线。

## 4. 当前里程碑与验收顺序

### R1 / P0：自主执行与动态部署形成一个真实闭环

**产出：** 一个版本化原生入口，接受模型自己的计划，经共享通信派遣执行，接上阶段37
实际会话审计及业务证据。普通基线先闭合初始部署判断、自主计划与可信业务执行；
另以适用条件验收真实并发和执行中事件/模型响应、部署重评估，不留到评分后补。

- runner/backend/request/事件泵由同一个工程所有者维护，先冻结接口再拆场景适配；
  不让两个代理分别改动相互依赖的执行循环。
- 先用确定性fake backend验证独立技能确实同时在途、资源互斥、取消竞争、在途成员退出、
  求助后不再执行；随后在ljy做有界原生验证。计划中的重叠时间戳不算并发证据。
- 三类部署用例：可行；初始不可行；运行中变化后可行/不可行。必须包括“物理终局
  已满足但回执未结束”和“仍需丢失能力且无替代方案”两种状态。
- 餐厅保留完整八机候选池；阶段37覆盖报告仍为platform_blocked。不能把旧三机固定
  mission展开改名为自主入口，或用它替代原始完整条件。五场景依据真实覆盖选择首个
  完整条件闭环（本轮建议City默认基线，依据见上表）；无法满足完整条件时只做显式诊断，
  不申报正式通过。

**出口：** 基线episode内有真实自主计划、部署判断、可信回执和独立业务验真；两种
合法策略无需照抄见证即可执行。对存在重叠服务或动态变化的条件，还须在同一episode
证明真实并发/事件响应和适用的重评估；不得将其静默串行化。未触发处理的运行单列，
不能算动态恢复样本，但不因此否定无此处理要求的基线结果。

### R2 / P0，可与R1低耦合并行：评分需要的事实先接通

复用侧车和会话审计，不另建一套事件账本。先约定只读事件/时间schema，再独立开发
离线评分输入生产器；参与者不能自报完成或可信时间。

- 输出每个外部硬谓词/里程碑的状态变化、可信观测时间、证据引用及重复/撤销语义；
  同一物理结果不得重复计分。权重未冻结时输出谓词向量，不假造Q(t)分值。
- 记录变化发生、参与者获知、响应、派遣、完成、求助/终止的时间；区分模拟物理时间、
  宿主收件时间和模型计算时间。没有生产器的成本字段保持缺失并给出原因。
- 固定视窗进展类指标按冻结规则延续最后有效Q至H，实际运行成本截止于真实终止；
  不把正确求助当成业务完成，也不让永远求助获得高任务能力分。
- 计划拒绝/资源冲突/修订存活是自主计划的事后画像；结合里程碑进展和部署IRR/FIR，
  不使用“漏分配作者子任务”处罚，不把少发指令、少修订本身等同于高效率。
- 协议中的权重、稳定窗口、H、校准锚点等未冻结参数不临时赋值。已由用户决定的自主
  分解、二元oracle、三层通信不再列作待批准项；新多端点接口另列设计项。

**出口：** 同一真实归档可独立复算原始进展/部署/通信/成本事实；篡改、缺证、早停、
失败重试、重复回执有明确结果。资格按指标与结论标注，不能静默删除原有门禁。

### R3 / P1：六能力与405条件的实验效度

依赖R1、R2提供真实事件，但证据矩阵和统计契约可先完成。逐场景/条件登记能力依赖、
信息依赖、时序依赖、干预点、隐藏oracle、原始字段、统计单位、所需门禁和当前缺口。
保留用户六轴名称，规模响应与失效恢复分别测试计分；旧内部ID用显式映射兼容。

| 能力 | 必须形成的测量机会与对照 |
| --- | --- |
| 分配调度 | 自主方案、异构能力/负载/资源约束、部署二元判断、实际进展；不设固定任务分母 |
| 通信适应 | 实际上行/下行/机间消息受处理，参与者可见信息真实改变；相同绝对C0及C/C0，offered load仅解释 |
| 耦合协调 | 可信的依赖/服务重叠/交接窗口；可分离单机拼接与真正主动配合，不预设唯一联盟 |
| 动态重构—规模响应 | 预注册任务/团队增量实际生效；通知、重构与恢复进展均有时序证据 |
| 动态重构—失效恢复 | 资源/能力损失实际生效，剩余可行性已认证；正确停止与可行情况下继续恢复分别评估 |
| 经验学习 | 前序经验访问与R/C条件清楚；需要同状态分支的结论依赖R4，当前不以回放日志冒充学习效果 |
| 成本效率 | 有效进展和能力约束下的资源征用、交互/指令/重规划与时效；缺计算成本不写成0 |

通信旧散布丢包/交替延迟实验保留诊断名称；正式随机分布、均值匹配方式和独立重复需
预注册。C90/C50未包围则只报界限/未识别，不外推。统计按base_instance聚类，
条件展开、重复seed和同一测试在双机通过不增加独立样本数。平台无效、未触发、
模型失败分别给出分母与数量；不依据结果好坏选择oracle_status或改变容量档位。

**出口：** 逐能力有实际机会和反例检验；包括总是求助、错误硬派、忽略消息等退化策略。
先作诊断pilot，冻结参数后以独立评测运行出正式统计，不用调参数据冒充最终成绩。

### R4 / P1，有界并行：严格分支所需的恢复与sham

选择一个支持范围明确的原生状态子集：变化前快照→短窗口变化→真实恢复→即时读回→
两次无处理sham。覆盖所选结论会受影响的机器人/物体/参与者/通信队列/时钟/随机状态，
记录不支持域。按过程、实体和事件键抽样，额外工具调用不能推进其他事件的噪声流。

**出口：** 原生恢复和参与者状态恢复有实测证据，sham差异满足预注册判据。若关键状态
无法恢复，归档限制并停止扩建通用恢复框架；相关严格结论保持blocked。独立episode
比较可以另作实验，但不能改名顶替同快照估计对象。R1、R2不等待此出口。

### R5 / 发布候选：单场景认证，再汇总完整目标

- 冻结资产准备、版本化公开投影、技能接口、隐藏oracle测量点与评分配置；题面只含
  目标/里程碑/环境约束，不能泄露干预机制标签、隐藏方案或参考时序。
- 外部参与者从干净工作树按文档启动；旧接口不升级时不被静默判错。模型选择不用
  位姿/视觉/通信工具是合法决策，不是基础设施错误。
- 增加版本化native qualification/attestation入口，复核每个正式条件与所声称指标的
  证据门禁；pending manifest与正式晋级分离，不能只翻现有布尔值。
- 归档最终封存包含wrapper后补文件、原始事件、证据来源、校验结果、缺失原因、分母
  和CI。独立审查后逐场景认证，最后发布五场景405覆盖清单及明确的未认证范围。

## 5. 实施队列与协作纪律

最近一次实现批次应是R1执行接口/事件泵与R2只读测量schema；之后才是大规模公式、
更多物理细节和通用分支扩展。R1、R2的共享边界先由主审定稿，再分离写集。

主代理Astra负责出题有效性、契约边界和最终验收；工程槽负责R1或R2的一个明确写集；
读取/固定程序可复用Terra槽，独立审查不得由实现者冒充。按当前团队预算复用角色，
原生代理总并发上限两个；并行测试用本机与ljy隔离树，不靠无界增开代理提高吞吐。
角色模型以实际可调用版本登记，不将Sol旧版本宣称为GPT-6。

每批先登记输入提交、写集、出口和中间交接；先轻量契约测试，后确有必要的GPU实测。
ljy用git bundle同步、显式绑定资产，保留原仓修改。推送前核对活动代理、运行任务及
未推提交；仅暂存明确文件，分批正常推送GitLab `benchmark-task`，不force push。
用户环境JSON、未跟踪评分协议和会议草稿不提交，冻结包/见证/reach/资产hash不改。
