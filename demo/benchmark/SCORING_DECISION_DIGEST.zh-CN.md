## 2. 第一档逐项决策卡（10 张）

### G1 ×10 重复的层级归属
- 问题：原则 1 的"同任务×10"落在哪一层统计？
- A：×10 = base_instance 实例内重复（含 channel seed 等随机源），先实例内均值、再以 base_instance 为统计单位。
- B：×10 = 10 个独立 base_instance，扩大独立样本数。
- C：×10 = 学习轴轮次，与 R/C 经验保留混同。
- 推荐：**A**——与协议 §2.6 层级和 `communication_analysis.py` 现实现一致；R3 明文"条件展开、重复 seed 和同一测试在双机通过不增加独立样本数"直接排除 B；C 与 XL1 的 R/C 配对轮语义冲突。
- 锚点：原则 1（矩阵 §0 原则 1）；矩阵 §7.1；路线图 R3。
- 不拍的阻塞面：R3 统计契约的统计单位/聚类/配对条款；矩阵 §7.1 明令拍板前不得把 10 个同任务 episode 当独立 base_instance。

### G2 实例内重复数 K 与聚合公式
- 问题：K 取值与两层聚合公式是否现在冻结？
- A：K=10（承接 ×10），聚合 = 实例内均值 → base_instance 聚类 bootstrap，六轴统一。
- B：K 与 ×10 分离（如按条件拆分重复预算），×10 只解释为总预算。
- C：不统一公式，逐轴自定义。
- 推荐：**A**——与 G1 同一决策的两半；六轴共用配对身份与聚类（矩阵 §7.1/§7.3）。
- 锚点：原则 1；矩阵 §7.1；路线图 R3"统计按 base_instance 聚类"。
- 不拍的阻塞面：R3 预注册的重复/seed 条款；学习轴 registry 的重复轮次供给无法登记（矩阵 §5.5）。

### G3 逐任务族 H 的取值规则（联动 TC7）
- 问题：每任务族评估时限 H 怎么定？
- A：题包冻结时逐任务族预注册：以见证/参考解完成时间为基准的固定倍数（倍数预注册，数值 pilot 后、正式运行前冻结）。
- B：全局统一常数 H。
- C：运行时动态延长。
- 推荐：**A**——任务族时长量级差异大，全局常数不可比；动态延长被 R2"固定视窗进展类指标按冻结规则延续最后有效 Q 至 H"排除。
- 锚点：路线图 R2（H 属"不临时赋值"项，但规则可先冻结）；矩阵 §3.6 TC7、删失总则 §7.6。
- 不拍的阻塞面："H 内发生概率"类右删失统计（§7.6）无法预注册；时序/动态重构/学习/成本四轴共同前提（矩阵 §10.2）。

### G4 Q(t) 是否引入阶段拆分/重试扣分
- 问题：Q(t) 保持协议原式（权重里程碑加权和），还是引入 RoboChallenge 式阶段拆分+重试扣分？
- A：引入两者：里程碑按任务合同冻结为带权阶段结构；同一里程碑重复尝试按预注册系数递减计分；系数占位、pilot 后定值，定值前 Q(t) 按协议原式 raw-only。
- B：只引入阶段拆分，不扣重试（浪费性重试只靠成本轴三层计费兜底）。
- C：保持协议原式。
- 推荐：**A**——原则 4 明确包含"阶段拆分/重试扣分"两个成分；矩阵 §7.7 已注明这是协议修订级决策、未拍板前按原式，本推荐即行使该修订权。
- 锚点：原则 4（矩阵 §0 原则 4、§7.7）；路线图 R2"权重未冻结时输出谓词向量，不假造 Q(t) 分值"。
- 不拍的阻塞面：Q(t) 生产器的权重 schema；R2 谓词向量转正条件；四轴统计契约（矩阵 §10.2）。

### G5 重规划三层计费的层定义（联动 CE5）
- 问题：原则 3 的"三层"怎么定义？
- A：采纳矩阵候选解释：L1 首次规划（基准费率）/ L2 外生必要重规划（必要成本，不计浪费）/ L3 无收益重规划（高费率，计浪费）；层归属由评测器注入日志判定（§4.3 门禁 1），L3 依赖 replan_pre checkpoint 配对。
- B：按计算耗时分档（快/中/慢）——与协议"无收益重规划"诊断语义不符。
- C：只分两层（首次/重规划）——丢失"无收益"信号。
- 推荐：**A**——协议 §6.3 门禁 5"动态重构触发的必要重分配/重规划不计为成本浪费"正好支撑 L2 与 L3 的分界；矩阵 §6.6 已把该候选列为"待拍板解释，非冻结定义"。
- 锚点：原则 3（矩阵 §0 原则 3）；矩阵 §6.6 CE5、§6.3 门禁 5。
- 不拍的阻塞面：成本轴统计契约、R2 声明前成本截点、`planning_compute_cost_s`/`replanning_compute_cost_s` 生产器语义。

### CE5 三层计费的费率结构与呈现
- 问题：三层成本以什么形式进结果：标量计价还是分层向量？

- 推荐：**A**——矩阵 §6.1 冻结方向是"成本向量 + Pareto 支配而非标量总分"；标量化需费率定标（pilot），且与 §6.1 冲突。
- 锚点：矩阵 §6.1、§6.6 CE5；原则 3（层定义随 G5）。
- 不拍的阻塞面：cost_evidence 字段分层维度与 R2 成本 reader；G7 合成分决策的输入。

### TA2 自分解分配可执行性校验的范围与严格度

## 4. 三个关键决策点（矩阵 §10）

### 决策点 1：自分解主线下任务分配轴的正式公式（TA1 + TA2）

**决策问题**：Goal 自分解主线没有固定子任务集合，任务分配轴的"正式结果"到底是
什么——只有部署四类率，还是加上自分解可执行性指标？这决定本轴能否脱离
`not_applicable_protocol_mismatch`（矩阵 §10.1）。

**推荐方案**：两步走。(1) TA1 选 A：部署四类率（correct_deployment /
correct_refusal / false_refusal / false_deployment）作为本轴唯一核心正式结果，
沿用 IRR/FIR 命名、按阶段48真值类条件分母重定义——FIR = oracle 判可行却拒绝的
条件率，IRR = oracle 判不可行却部署的条件率；机器名与 mapping v4/v5 现实现对齐，
另加新名别名映射作协议兼容层。(2) TA2 选 A：可执行性校验器只做能力-载荷匹配、
接口可用、资源冲突的最小检查，raw-only 诊断、不进正式分母、不与作者 witness
匹配；若将来要复活 VAR/FSR 等价物，须按矩阵 §1.5 单独注册生产器、不与部署层混算。

**理由锚点**：原则 7（IRR/FIR 真值类条件分母）已由阶段48实现，是三个关键点中
唯一已有落地代码背书的；原则 5（搬运/检查非独立任务）与路线图 R2"不使用'漏分配
作者子任务'处罚"共同排除按作者子任务计漏分配；矩阵 §1.5 分母政策（分母锚定
oracle epoch，与模型拆出多少任务无关）。

**影响面**：拍板后 SCOREABILITY_REASONS 第 1 条
（`fixed_subtask_metrics_require_revision_for_goal_decomposition`）的解除条件
完整（矩阵 §8 首行），R3"分配调度"行的统计契约（自主方案、部署二元判断、实际
进展、不设固定任务分母）可起草。不拍则本轴与 R3 分配行全部停在
`not_applicable_protocol_mismatch`。注意：本拍板只是定义层授权，实现层验收前
仍 raw-only（矩阵 §8、§7.8）。

### 决策点 2：Q(t) 进展底座（G3 / G4 + TC1–TC7）

**决策问题**：时序/动态重构/学习/成本四轴共用的进展底座 Q(t) 用什么公式与时限
框架——权重结构（是否引入阶段拆分与重试扣分）和逐任务族 H 的取值规则（矩阵
§10.2）。

**推荐方案**：分两层拍板。规则层现在定：(1) G4 选 A：Q(t) = 按任务合同冻结的
带权阶段结构之和（阶段拆分），同一里程碑重复尝试按预注册系数递减计分（重试
扣分）；系数先占位，pilot 后、正式运行前冻结；定值前 Q(t) 按协议原式 raw-only，
R2 侧继续"权重未冻结时输出谓词向量，不假造 Q(t) 分值"。(2) G3 选 A：H 逐任务族
在题包冻结时按参考解时长的预注册倍数登记（TC7 随之）。数值层延后：TC1–TC6
（采样、停滞确认/解除、容差、超时表、同步窗口）全部随 pilot 校准后预注册。

**理由锚点**：原则 4（进度分参考 RoboChallenge：阶段拆分/重试扣分）直接给出
方向；路线图 R2 把"权重、稳定窗口、H、校准锚点"列为不临时赋值项，但授权现在
冻结规则；删失总则（矩阵 §7.6）与一切"H 内发生概率"统计依赖 H。原则 6（六轴
名称不可改）不受本决策影响——改的是 Q(t) 内部公式，不是轴名（路线图 R3"保留
用户六轴名称"）。

**影响面**：Q(t) 生产器（`goal_progress_curve.py` 候选）、协调停滞状态机、Q_aff、
AUP/PGI/nPGI、成本同钟判定（矩阵 §7.2）全部以本决策为前置；R3 四行（时序协同、
两个动态重构子轴、经验学习、成本效率）的统计契约在规则层拍板前无法预注册。
不拍的最坏后果：实现者长期只用谓词向量，四轴正式统计无限期悬置。

### 决策点 3：跨回合学习 R/C 的记忆清空等价性与轮数（XL1/XL5 + G1/G2）

**决策问题**：学习轴 R/C 配对的严谨性边界——记忆清空"等价"如何证明、正式轮数
E 定多少、"同任务×10"是否落在本轴（矩阵 §10.3）。

**推荐方案**：(1) XL5 选 A：显式可写状态清单（对话历史、记忆存储、缓存、案例库、
反思日志等）+ 保留/清除差验证，接 checkpoint 七状态域与 SCORING_CHECKPOINT_DESIGN
§6 门禁 5 验收；未证明前 `retention_control_unverified` 只报多轮现象、不进严格
经验保留因果汇总（矩阵 §5.3 门禁 3）。(2) XL1：下限 E≥3 按协议，正式轮数 pilot
定（矩阵 §5.6 明示）；首轮主干共享且只执行一次（门禁 5 原文）。(3) G1/G2 选 A：
×10 落在 base_instance 实例内重复层、六轴共享；学习轴轮次 n 是 R/C 配对轮，与
×10 重复正交——即学习轴每一轮内部仍有实例内重复 K。

**理由锚点**：原则 1（同任务×10，矩阵 §0 标注书面 unknown，本推荐是其落点
提案）；协议 §3.5 R/C 配对语义；路线图 R3 经验学习行"前序经验访问与 R/C 条件
清楚；需要同状态分支的结论依赖 R4"；R4 出口（若关键状态无法恢复则归档限制）。

**影响面**：R/C runner、learning opportunity registry、checkpoint
`participant_recoverable` 域的验收标准；本决策点是 R4 sham/checkpoint 门禁的
第一消费者（矩阵 §10.3），其拍板结果直接决定 R4 的必要覆盖清单。不拍则学习轴
只能停在"多轮现象"层，且 G1/G2 的六轴统一聚合（第一档）连带悬置。
