# 隐藏剩余任务可行性 Oracle

正式问题是：从可信状态`S_t`出发，使用当前可用机器人池`R_t`和剩余资源，
是否存在至少一条满足全部硬终局谓词的合法完成路径。参与者与正式真值均只有
`deployable`和`not_deployable`，不公开求解路径、人员指派或执行顺序。

## 输出与统计边界

```yaml
feasibility_label: deployable | not_deployable  # 仅在 verified 时非空
oracle_status: verified | failed
```

`failed`时标签为null；该episode整体退出部署判断指标，单列评测基础设施缺口。
不得把它计为第三类任务、正确求助、错误部署或模型漏答。模型没有提交判断时，
若oracle已verified，应保留该测量机会及缺答事实，不能删掉分母或把oracle改为failed。
初始/运行中测量机会分别保留；具体IRR等公式仍须与协议的自分解主线定义对齐。

Oracle在当前轮参与者`act`之前求值并缓存。每个要求评估的epoch写入独立账本，
不以模型是否提交声明为条件；连续两次外生变化之间未作答的epoch也不能丢失。
注册表、状态域及失败规则在运行前冻结，禁止运行结束后根据模型表现决定是否剔除。

## 当前实现

- `goal_remaining_feasibility_oracle.py`：冻结测量点、状态域和转移模型；检查可信状态
  绑定；在有限状态图中穷举合法路径。搜索完无终局路径才返回not_deployable，
  搜索预算耗尽、未知状态、绑定错误、模型未认证均返回failed/null。
- 每个转移可要求多个不同成员同时提供能力/载荷；不指定机器人ID，枚举所有合法组合。
  多个转移允许顺序复用资源与成员，不把可串行化的冲突或缺冗余直接判不可行。
- `RegisteredRemainingTaskOracle`接runner的可信hook；量测provider只获取当前快照，
  不接收参与者声明、动作历史或作者见证。完整注册与查询证据私有归档。
- `goal_deployment_feasibility.py`保留必要条件内部诊断；它未覆盖完整剩余任务空间，
  不能独立给正式标签，投影到runner时明确为oracle failed/null。
- `goal_deployment_cases.py`生成五场景初始缺能力、唯一提供者退出、能力降级的作者候选。
  这些候选尚无完整原生oracle认证，正式标签为空；不得拿内部诊断结果冒充正式真值。

有限状态求解器的正确性不等于物理抽象的正确性。每个场景的模型必须经独立审核，
证明其转移代表可用合法技能、终局谓词等价于真实成功条件、所有合法替代路径均被覆盖，
且时间、通道容量、载荷、资源耗尽及必要服务没有被漏掉。只要模型不完备，
“搜索无路径”就不能证明物理世界不可行。现有参考世界测试均标
`exact_reference_world_only`；正式准入要求`native_remaining_task`的外部验证证据。

## 五场景下一验收矩阵

以下是隐藏量测要求，不是发给模型的子任务顺序。

| 场景 | 需要接入的可信终局事实 | 必须冻结的对照状态 |
| --- | --- | --- |
| 工厂 | 异常身份/当前独立观察、实际服务到达、维护交接 | 感知证据尚缺/已取得；关键通行能力退出前后；不为固定服务车虚构搬运要求 |
| 仓库 | 两订单对象的身份、稳定dock位置、交接回执、通道关闭状态 | 木箱/纸箱未搬、稳定中间位置、已到dock但未交接；单机替代/双机负载组合；剩余资源不足 |
| 房屋 | 椅子完整占地、书堆稳定与身份、整条通路净空、成员退出占地 | 家具未恢复/已恢复；书堆不同状态；仍有替代搬运组合/确无合法替代 |
| 城市 | 受影响人员完整身份与轨迹、到达、车辆保护、通路与服务回执 | 引导仍必要/已到达；持续服务是否仍需提供者；地面引导/空中服务合法替代及失效 |
| 餐厅 | 两区实际到达与支撑检查、当前观察、readiness回执 | 尚未检查/已检查；relay仍需/已完成；单机串行合法替代和剩余时间预算 |

每个测量点绑定任务/资产/接口版本、oracle注册哈希、触发事件、物理或明确映射的
时钟、当前池/能力/资源版本、完整量测摘要与证据引用。需覆盖初始部署、预注册成员
退出、能力失效和明确里程碑状态变化；不声称枚举模型可能造成的任意连续物理状态。
正式发布前，所有预注册点均须verified；不能可靠建模的任务族不进入这项正式统计。

## 阶段出口

1. 门禁和oracle调用时机回归通过；证明隐藏真值不进公开事件，且求助后无自主执行。
2. 五场景各自完成谓词读回与模型完备性审核；补齐上述状态矩阵，独立复验正反标签。
3. 发布审核检查注册表未变化、每个点都有原生verified证据且无质量失败；任何缺项阻断准入。
4. 通过上述门禁后再接正式IRR/误拒/错部署等统计；本阶段仍保持
   `execution_validated=false`、`business_outcomes_validated=false`、`scoreable=false`。
