# 三场景任务设计审查（S13）

本审查从出题人视角回答：生活或业务中为什么需要这项工作，被测模型实际决定什么，怎样判定结果，以及怎样避免把运动基线、脚本流程或题面标签当成智能能力。依据是当前 `scene_challenge.py`、Factory 专用编译器、`semantic_contract.py`、`domain_evaluator.py`、participant API、通信/团队协议和运行时准入代码。本阶段只修改 authoring、其测试及本文；没有运行 Isaac，也没有改运行时、场景编译器或评测器。

**结论：三个场景可以作为不同业务的受约束任务骨架；目前不能统称为自主业务规划、完整生产恢复或已验证的物理协作 benchmark。** Factory 的有效题型是证据驱动工位派遣；Warehouse/House 的有效题型是给定业务 DAG 下的分配与协调。领域验收谓词的存在，不等于传感器、领域服务和真实执行已提供了该谓词所需证据。

## 1. 当前题型与自然业务含义

| 场景 | 可出题的当前业务 | 交付结果 | 不应写入当前能力结论 |
| --- | --- | --- | --- |
| Factory | 待核对物料需要处置去向，机器人结合俯视与近景标记证据选择装配工位或 dock | 正确站点选择、决策所用消息的因果证据、提交之后的实测到达；fallback 单独报告 | 异常诊断、危险隔离、设备复位、生产恢复、任意物体识别 |
| Warehouse NVD | 核对指定订单物品，集货木箱与纸箱，把同一纸箱送到出库区并完成交接复核 | 身份与数量、集货和派送的所有权链、dock 状态与回执 | 多订单优先级优化、自主挑选 SKU、派送前 dock 放行、真实载荷协同 |
| Modern House NVD | 住户回家前整理指定扶手椅与书堆，机器人撤离后复核入口到生活区的连续通路 | 家具/小物正确交付、整理前后证据、最后一次机器人撤离后的连续净宽检查 | 自主找回未知物品、一般住户安全、人体接触安全、实物搬运能力 |

“搬运、扫描、等待”是这些任务的执行步骤，不能代替业务交付。例如，把另一个外观相同的纸箱送到 dock 应判错；扶手椅到达停车区但机器人挡住生活动线也应判错。这两种失败都可能同时拥有全部节点的调度完成记录。

当前场景 catalog 中的长远使命文字比上述实际范围更宽：Factory 使用 `production_exception_response` 家族名，Warehouse 文案出现“出库前复核”，House 出现“找回”。S13 authoring v2 提供了范围准确的 `mission_brief`、`participant_decides`、`fixed_by_author` 和 `forbidden_claims`。既有 ScenarioSpec、公开编译包和节点 ID 保持兼容；**本文和 authoring 修改不会自动重写旧发布包中的文案**，发布者必须另行检查并重新编译。

## 2. 每个场景的出题骨架

### Factory：有依据的工位派遣

固定流程是 `aerial_view → ground_approach → ground_view → route_confirmation`。前面三阶段由 benchmark 管理；模型控制最后的派遣，使用 `consume_message`、`wait`、`navigate_goal`。公开业务规则给出候选 `assembly_site` 与 `dock_site`；私有标记真值决定本实例正确的选择。

自然问题是“同一待检物料应送往哪个作业站”，不是“依次走四个点”。高处观察与近景观察应有不同的信息贡献，例如遮挡使单一视角不能确认标记。只有当真实观测/消息确实改变可用信息、模型消费证据后作出选择，才能讨论信息融合或通信效应。两台传感器都直接提供相同完整答案，不足以证明异构感知互补。

场景内的工位、通道、物料标记可以承担题目语义。catalog 的 `safety_beam` 只是设计资产；没有隔离动作与安全服务状态，不能据此宣称完成危险隔离。视觉标记/代理物体必须公开说明是识别任务代理，不冒充真实工业缺陷识别。

若未来要出“恢复生产”题，需要另外冻结异常状态、隔离权限、操作动作、复核来源、恢复放行谓词及失败条件，再新增经审查的任务族。不能靠把 `route_confirmation` 改成“恢复生产”来扩展范围。

### Warehouse：订单正确性与交接链

保留的十个节点及其业务含义：

| 节点 | 业务目的与边界 |
| --- | --- |
| `rack_overview_scan` | 获取指定货架区证据；拍到图像本身不等于识别 SKU |
| `aisle_left_access`、`aisle_right_access` | 到达两侧作业位；两侧都就绪后才进入联合转移 |
| `oversized_crate_transfer` | 木箱进入集货区并保留双成员所有权事件；两人要求尚无物理必要性证明 |
| `priority_carton_stage` | 指定纸箱集货；`priority` 名称不是订单排序策略 |
| `dock_lane_check` | 地面到达 dock 作业位；到达本身不证明接收权限 |
| `priority_carton_dispatch` | 把刚才集货的同一纸箱交付到出库区域 |
| `outbound_inventory_scan` | 当前是在派送完成之后取证，不能变成派送前门禁 |
| `dock_confirmation_hold` | 为交接留出观察窗口；等待不等于收货回执 |
| `aisle_closeout` | 作业结束后的回位记录，不等于全仓通道已释放 |

当前 native 道具为 `wooden_crate_a` 与 `cardbox_c`，符合仓储常识；`nvd_pallet_asm` 只是 catalog 中的候选，不是默认实例必有的第三件道具。具体尺寸来自资产声明，不从资产名猜测。“大件”是物品/作业语义，不能直接推导 Carter/M20 的载荷能力。

LLM 可更换已审核的布置与团队配置，但必须保留纸箱的 stage→dispatch 对象身份、木箱/纸箱角色及因果前置关系。当前模型不能重新选择订单、SKU 或任意货物，也没有多订单簿与 deadline 排序验收，因此当前题面用“指定订单”比“优化优先订单履约”准确。

### House：整理后确实恢复生活动线

保留流程：入口取证 `room_entry_scan`，两侧接近 `furniture_side_access` / `doorway_access_check`，联合整理 `coordinated_furniture_reposition`，移动后取证 `furniture_clearance_scan`，书堆暂存 `keepsake_relocation`，地面复核 `room_entry_verification`，复核者与作业者分别撤离 `reviewer_standby` / `hall_release`，最终扫描 `room_condition_scan`，观察窗口 `placement_confirmation_hold`。

使用 `mh_armchair` 和 `mh_bookstack`，对应扶手椅与书堆。历史 `keepsake_box_proxy` / `keepsake_relocation` 是兼容 ID，不能据此把实际书堆解释成保险箱或失踪珍宝。`mh_bowl_brass` 可作自然家居地标，但默认任务没有强制实例化它。

业务目的应是恢复指定的入口—生活区通路、妥善放置住户物品。最后的连续通路检查在机器人撤至独立待机区之后进行，避免拍照时暂时让开、最后又堵住通道。隐藏领域契约当前检查声明的地面动线至少 0.8m 净宽；这个数值是题目阈值，不是普遍安全法规或无障碍认证。楼上生活空间、人体接触、家具倾覆和抓取损伤均不在该二维谓词的证明范围内。

## 3. 三种模型/角色的输入输出必须分开

| 角色 | 获得什么 | 能决定什么 | 不能得到/提交什么 |
| --- | --- | --- | --- |
| 出题 LLM | authoring v2、固定角色和技能、资产目录、可用因子与限制 | 在允许范围内生成 ScenarioSpec；建议布置与团队，提出待审查的私有实验计划 | 不能通过写 `success=true`、`execution_validated=true` 或新技能名称获得支持 |
| 被测模型 | `public_task.json`、`participant_api.json`、运行时已公开的事件 | 在当前启用 API 中做选择；Factory 为证据消费/等待/站点选择，Warehouse/House 为固定 DAG 的成员分配/重分配及允许的导航动作 | 不获预知退出/加入时间、reserve 身份、对象真值绑定、未来丢包/到达时间、参考分配或可行性见证 |
| 出题 harness / 隐藏评测器 | 冻结实例、私有领域绑定、干预计划、真实观测、所有权/服务/轨迹账本 | 施加已支持干预、记录证据、重放、评分 | 不接受被测模型自报的位姿、成功、物品身份或安全布尔值作为测量证据 |

公开任务已包含目标区、机器人声明能力、objective DAG、资源与业务要求。NVD `scene_objects` 当前提供匿名 ID、asset_key、size、mass；没有通过这个字段提供对象真值身份，也没有提供对象位姿字段。场景资产和可见观测的获取仍应按实际 API 说明，不能用作者持有完整 USD 的知识替模型补齐隐含输入。

NVD 默认运行时启用 `allocate`、`reassign`、`navigate_goal`、`consume_message`；运输目的地仍固定。观测只有通过隐藏条件控制的通信队列实际送达后才能消费，依赖节点据此放行。协议组件模式额外支持 participant `wait`，但通信接入不等于 SKU/室内语义 detector 已部署。动作字典里出现一个名称，不意味着本轮模型真的有相应控制权。

当前没有模型输出可执行子任务 DAG 的接口。将已给 DAG 重新复述、换执行成员或生成解释文字，不计“自主分解”。未来自主分解轨道需要只提供业务目标与可用原语，让模型决定对象、顺序和备选方案，并由独立验收器判断多种合法计划；这必须作为另一个明确版本，不能与当前成绩混算。

## 4. 理论可行性见证与候选数

S13 的 `build_authoring_witness(scenario, ...)` 不调用 Isaac、不读地图、不导入资产场景；它使用现有公开接口资格判断，按 DAG 拓扑顺序构造串行团队见证。串行化使共享资源在此抽象模型中不重叠。输出仅供作者/评测器，不能加入 participant packet。

默认 `iris_1 + m20_1(Z1) + carter_1` 的声明级候选数：

| 原语/决定 | Warehouse | House | 解释 |
| --- | --- | --- | --- |
| 每个 `aerial_scan` 节点 | 1 个候选 | 1 个候选 | 只有一台已声明的空中机器人 |
| 每个 `transport_object` 节点 | 1 个候选 | 1 个候选 | 当前公开资格要求操作接口，只有 M20 的 Z1 满足 |
| 每个 `joint_transport` 节点 | 1 对候选 | 1 对候选 | 两个地面成员组合成一对；不是“两种备选方案” |
| 每个普通 `navigate` / `wait` 节点 | 2 个候选 | 2 个候选 | 接口资格允许两台地面机器人；未筛掉具体路线/时限不合格者 |
| 全 DAG 的声明分配组合数 | 32 | 64 | 串行、相互独立的节点资格乘积，不是 32/64 条真实可执行解 |

Factory 不使用该 NVD helper 代替专用 QA。它对模型公开两个工位候选，但实例真值通常只支持一个正确选项；两个目标候选不能计成两个机器人团队候选。

见证的前提包括：被排除的前置工作已完成、每个原语可以在时限内完成、允许串行执行、当前团队快照期间无新能力变化。它不证明候选路线、旅行时长、电量、抓取、载荷、三维通行或领域感知成功。`validate_authored_business_scenario` 仍调用既有几何/连通性/执行路线准入；其通过也不证明所有候选组合都能执行。

应保留以下层次：

1. `candidate_count == 0`：在声明条件下没有团队，应拒绝通常的可解题发布；若研究不可行性识别，必须预先定义独立轨道和正确拒绝答案。
2. `candidate_count == 1`：该节点测执行资格与协调遵从，不宣称分配选择难度。
3. 多个声明候选：才有初步选择空间，后续仍要逐候选检查路线/时间/载荷，记录过滤原因。
4. 存在完整且具证据的参考执行：才有部署可行性依据；参考轨迹不应泄露给被测模型。

两成员约束本身不足以证明协作必要性。需要比较保持业务要求不变时的单机/同构替代，并给出确切失败理由，如视角不可替代、单机不能完成的同时操作、经校准的尺寸/载荷限制。现有未知 payload rating 不能被作者随意填成较小数字，以“证明”必须联合搬运。S13 固定原生尺寸和目录质量估计，质量估计仍不是机器人额定载荷。

## 5. 团队变化与通信变化如何成为有意义的题

| 业务动机 | 作者需要冻结的条件 | 应观察的模型能力 | 当前边界 |
| --- | --- | --- | --- |
| 工厂巡检交班 | 哪一成员何时退出、替班成员何时公开、未完成的观察职责 | 是否避免依赖已退出的观察者，是否正确使用已有证据 | F-INS 当前不等于已支持任意队伍干预 |
| 仓库载具回充 | 执行窗口、载物时是否退出、预注册替补、后续订单步骤 | 资格重选、释放/接管、业务对象身份连续性 | 不能把“回充”文案当成已仿真电池模型 |
| 家居设备结束服务/能力失效 | arm/传感器能力的新版本、未完成书堆/家具任务、停放责任 | 是否重新检查资格而非复用旧 robot ID | 物理换装或控制器失效尚无对应 live 结论 |
| 金属货架/房间隔断影响报告 | 发布内容、采集时刻、TTL、recipient/channel、改变时刻和条件 | 使用新鲜可见消息、等待/重规划、避免重复或过期消费 | 是确定性通信模型，不是无线传播实测 |

当前 `TeamLifecycle` / `InterventionSession` 已有 reserve 注册、加入、退出、能力版本和释放义务协议。运行时另有受限的已有地面 articulation 替补路径；Warehouse/House 需要 participant 边界，任务中可有不参与替换的空中观察者。动态生成新机器人、物理能力重配仍不能从协议成功推断出来。以具体 runtime preflight 和执行报告为准；此处只盘点代码范围。

作者应在事件前后分别调用见证 helper 检查剩余任务：退出唯一带臂成员后纸箱/书堆节点可能变成零候选；退出任一地面成员后联合搬运可能变成零候选。预声明备用成员在 `active_agent_ids` 中加入，才计入下一份假设快照。`remaining_node_ids` 必须包含尚未完成前置节点的所有后继；不能删去依赖来伪造可行。能力变化可用显式修订的作者配置重算。

这些快照不执行生命周期事件，也不能证明物体在退出时已释放。载物中断需要独立的实测所有权、释放位置、接管和最终交付证据；不能把两份分别可行的静态见证拼接成一次恢复成功。每个变化阶段至少记录：输入快照 hash、活动成员、候选数量、零候选原因、既有对象所有权、所用能力版本及尚缺的执行证据。

通信报告 v2 已保存初始与最终契约，并重放条件改变；作者应把评测器冻结的初始契约提供给重放校验。全丢包若切断完成业务所需的唯一信息源，必须承认可解性发生变化：要么预先提供合法替代观察，要么改为评估合理拒绝/报告不确定性，不能要求模型猜隐藏答案。

## 6. 单因子可辨识，不靠相同 seed 或相同 hash 标签

`validate_authoring_factor_pair` 比较两份完整的作者侧输入：

- `scenario`：相同节点、目标、资产尺寸、质量、robot/controller/attachments、初始位姿及 seed。
- `observation_inputs`：相同内容、采集/发布时间、身份条件和 TTL。
- `budgets`、`scoring`：相同时间、模型预算、评分阈值和必要领域条件。
- `reserve_pool`：相同候选备用资源，不能只给变体额外能力。
- `factor_levels`：覆盖该场景已审核的所有因子，恰好一个等级变化。
- `interventions`：通信和生命周期两份显式计划，只允许所选因子的计划变化。

例如，比较 immediate→delayed 时，不能顺便把书堆换位置、加入新机械臂、延长 TTL 或减少必要业务证据。helper 会拒绝这些输入差异、只改等级标签没有修改干预计划，以及同时改变通信和团队两个等级。它读取实际输入，不接受“两个文件 hash 一样”的自报作为依据。

该 helper 的 `validated` 仅表示**提交输入的隔离性**。它没有运行计划、没有判定计划是否正确实现等级，也没有证明本次消息进入模型的决策窗口。`factor_effect_validated` 和 `execution_validated` 始终为 false；其 `remaining_gates` 明确要求等级→干预语义校验、干预重放/可观察性，以及干预后的可行性判断。无效动作或发生在所有决策之后的延迟变化，不是有效通信难度实验。

涉及 aisle/room 几何、payload 或观察身份变化的因子，不能要求两份整个场景完全一致，也不能免去冻结检查。它们需要另写场景专用差异白名单和几何/领域审核。当前 helper 明确拒绝替这些轴做通用比较认证。`order_priority` 只有目录等级，没有自主订单选择和排序验收；`payload_team_need` 只有运动学团队约束；不能把这些目录等级当作已执行的因子 sweep。

统计发布还应预先固定开发/留出 split、每个条件的重复次数、随机种子配对、模型 token/时间预算和失败分类。报告业务成功、协议正确性、恢复、基础运动失败四项，避免把运动控制器倒地直接解释成 LLM 推理差。本文没有生成统计结论。

## 7. LLM 受约束再生成和本阶段机器检查

输入给出题 LLM 的是 authoring v2；输出仍是既有闭合 ScenarioSpec。新的作者侧见证、因子比较计划和报告放在独立私有记录中，不塞进 ScenarioSpec 或 participant 输出。

| 生成步骤 | S13 检查 | 拒绝的反例 |
| --- | --- | --- |
| 选择任务族与模型决策范围 | 固定 `evaluation_track`；NVD validator 拒绝其他轨道 | 将同一个给定 DAG 声称为 autonomous decomposition |
| 保留业务角色 | 复用已有精确节点 ID/skill/target 映射 | 把普通 navigate 改名为 SKU 核对 |
| 保留业务因果 | 检查经审核的前置关系，可接受等价的传递前置路径 | 未集货就派送；机器人撤离前做最终居家扫描 |
| 选择并绑定道具 | 角色→asset_key、目录尺寸/质量估计、可移动模式 | 仓库木箱换扶手椅；把椅子缩小；使用静态不可移动载物 |

| 比较实验 | 核对实际冻结输入与唯一变化的因子 | 延迟比较中同时增加模型预算、改变观察答案或备用团队 |
