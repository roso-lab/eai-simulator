# 阶段57：餐厅初始正向可行性证书接线

输入为阶段56 `e9b0c40`。本批是R1的事前初始判断组件，保持完整八机候选池和自主拆题。
不改变任务、作者见证、几何、reach、预算或发布标志。R1–R5尚未完成。

`RestaurantInitialPositiveOracle` 接收独立固定摘要的隐藏证书及可信执行输入，在初始
epoch检查题包/部署/条件、八机状态域、成员与资源版本、源码、资产和运行配置，然后复用
剩余任务求解器。只有已验证的正向路径返回deployable；缺证、域外、求解失败和求解器的
负向结果全部返回内部failed/null。部分路径搜索失败不能证明不存在其他方案。

证书中的Carter双路线、观察和回执是隐藏的存在性构造，不会公开给参与者，不限制其
选人、计划或顺序。该构造的固定窗口是导航[0,60)、观察[61,71)、回执[72,82)，包含两段
调度间隔；82秒小于任务原有240秒预算。合成测试证书只支持明确的fixture状态，不能
用于native初态。判断按episode/assessment epoch冻结，后续成败不回填初始真值。

公开诊断入口新增可选评测侧参数：

```text
--initial-oracle-inputs
--initial-oracle-certificate /absolute/private/certificate.json
--initial-oracle-sha256 <independently-pinned-canonical-sha256>
```

第一项只归档校准所需的可信输入，不创建证书；后两项必须成对提供。未提供证书的诊断
仍可运行，维持failed/null。证书及构造不进入public_task、参与者事件或计划接口。
评测器在参与者构造前固定证书，context在参与者初始化前记录评估；另外归档只含摘要和
评估结果的 `initial-oracle-report.json`。`initial-oracle-inputs.json` 是私有评测证据。

可信输入复用现有资产依赖图，包含机器人USD、控制器源码/权重和四份餐厅产品，当前为
35条路径及内容哈希，并核验源场景摘要。源码清单把机器绝对路径规范为仓库相对路径或
声明的控制器身份，不忽略不认识的外部文件。运行配置记录Python/Isaac/Torch等版本、
物理设备、预热、tick上限、通信处理开关；实际seed和物理设备单独读回，避免只存请求值。
